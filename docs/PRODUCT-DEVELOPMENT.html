1 · 產品定位

SGenAxis 是本機優先的跨平台桌機「自動化開發控制中心」：人選專案與工項、核准意圖與驗收；系統派本機 Agent CLI、收集證據、管理 Git 與（後期）部署。

體感目標：ComfyUI 式輕盈（薄殼 + Web UI），但是正式桌機 App，不是純瀏覽器工具。

使用者旅程（首版）

  1. 開啟桌機 App → 選／開專案
  2. 看工項燈號看板 → 篩選紅／黃／灰
  3. 指派 Agent → 看 Run／Log
  4. 檢視 Git 變更 →（後期）核准提交／發布

操作步驟（開專案／DryRun／設定、埠 28789 與 :8788 禁區）： apps/sgenaxis-desktop/README.md「使用說明」· 索引 docs/DESKTOP-APP-USAGE.md（PD-README-APP-01）。

範圍與非目標

首版範圍非目標
Windows／macOS／Linux 桌機；單一進行中 Agent；Git 先讀後寫；本機專案根綁定 多租戶 RBAC、雲端 worker、多 Agent 並行、外掛市場；HoneyBadger :8788 不當產品通道

6 · 功能說明（模組）

實作只依賴 Port。下表延續舊 product-plan 責任劃分；宿主為 Tauri，UI 為 Vanilla。

模組名稱功能摘要
HOST桌面宿主與建置生命週期、composition root、Tauri IPC、設定；不擁有業務狀態
UI工程控制台畫面與互動；mutation 經 command
WORK專案工作區專案 ID、root 綁定、切換與租約
SPEC工程規格ModuleSpec、契約、BDD／TDD；核准後不原地竄改
FLOW流程與核准工項階段、核准閘門、合法轉移
EXECAgent 執行Run、取消；兩種 Provider：CLI／地端 MCP（見下）
GUARD開發邊界封包完整性、允許／保護路徑
EVID驗證證據不可變測試紀錄、有效 RED／GREEN
GIT版本控管讀寫 Git；寫入需閘門
REL部署與發布打包／安裝／核准／回滾（後期）；Windows 走 WiX

首版功能優先

  1. HOST + UI 空殼（階段 1）
  2. 髒更新 + WORK 投影（階段 2）
  3. Path／FS／Process stub→真適配器（階段 2.5）
  4. FLOW 燈號 + EXEC DryRun→真 CLI + GIT 唯讀（階段 3）
  5. 看板／選單接 command（階段 4）
  6. GUARD／EVID／SPEC 加深 → REL／REPORT

Agent 約束

  • Run 綁定專案 root、工項 ID、工作樹指紋
  • Provider 完成 ≠ 工項綠燈
  • 取消／崩潰需對帳；禁止盲目重跑 mutation
  • 首版單一進行中 Agent
  • UI／FLOW 只選 Provider 種類 + 設定，不直撞 CLI 或 MCP

Agent 兩種接入（已拍板）

同一 AgentPort，兩套 Adapter，共用 Run 事件流（started／chunk／progress／exited／failed）：

模式名稱做法適用
A. CLI 原設計 ProcessPort 啟動本機 CLI（Claude／cursor-agent／Codex／Antigravity 等），讀 stdout／stderr／結束碼 腳本化、可離線重現命令列
B. MCP 地端 Agent 經 MCP 連本機／區網 Agent（stdio 或本機 HTTP／SSE），工具與訊息走 MCP 協定 對接已開的地端 Agent／IDE MCP 宿主 
UI「指派 Agent」
  → command: start_run { provider: Cli | Mcp, … }
    → EXEC 選 Adapter
        ├─ CliAgentAdapter  → ProcessPort → 子行程
        └─ McpAgentAdapter  → MCP client  → 地端 Agent
    → 統一 Domain Event → Dirty → 投影（Run log／燈號）
  • 兩種皆須：啟動、串流、取消、結束對帳、錯誤分類
  • 設定分開：CLI 路徑／參數 vs MCP 端點／伺服器名／核准工具表
  • DryRun 兩種皆可只模擬事件
  • 首版不強制同一 Run 雙通道並行
  • MCP 只連使用者明示的地端目標；秘密不進 UI 投影

監聽：CLI 用 pipe；MCP 訂閱通知／串流，轉成同一套 AgentChunk 類事件。

面定案

M4 包裝macOS／Linux 契約／stub／文件／CI 矩陣占位；可重跑、可標狀態；不硬套 WiX
非 M4 包裝SSH／容器／DCC 宿主另案；不併入「跨平台安裝包已完成」；SSH／遠端／容器開題見 docs/SSH-REMOTE-CONTAINER-EPIC-SCOPE.md（未接通；禁止暗示已接通）
做不做（禁止暗示已完成）
PackSpec 產物欄位與 Build Result／releases 可掛接宣稱已完整跨平台發行或全 OS 靜默裝卸皆綠
mac／linux 包裝 stub（無對應主機 → NOT RUN）強制 notarize／App Store／發行版商店必過
CI／文件三 OS 占位；缺 runner → NOT RUN付費 mac runner 才算 M4 過關
文件寫清 WiX 僅 Windows把 WiX MSI 成功寫成「三平台已發行」

Build Result／PackSpec 狀態僅：PASS｜FAIL｜BLOCKED｜NOT RUN｜PARTIAL。

  • NOT RUN：主機 OS ≠ 目標、缺 runner、elevated／notarize／真機裝卸未執行；exit 可為 0，不得記成 PASS
  • PARTIAL：契約／stub／文件到位，真機驗證或簽章未跑
  • PASS：該列目標上驗證實際跑過且通過；不可用「腳本存在」代替

Stub／文件／Windows WiX MSI ≠ 跨平台發行完成。對照 docs/CI-OS-MATRIX.md；桌機 README 同步本節。

7.1 滅燈規則（硬性 · 已拍板）

工項改綠（滅燈）必須同時滿足：

#條件不合格例
1有產出（可指認源碼／報告／產物路徑）空承諾、只改備註、只改 zone
2獨立 TDD Agent 親跑／核對並回報 TDD_PASS實作代理自測自報、PENDING_TDD_PACKET、弱化 assertion
角色可做不可做
實作 Agent寫碼、交報告、標 READY_FOR_TDD改綠、自稱 TDD PASS
TDD Agent定義／跑測、寫 *-TDD-REVIEW.md、TDD_PASS／TDD_FAIL代做業務功能
母對話／owner僅在 TDD_PASS＋有產出時改綠只憑實作口頭完成改綠
  • 禁止排程／腳本批次直接改綠
  • 禁止實作代理自測通過就滅燈
  • poll_next_work.py 只列待做；poll_extinguish.py 拒絕直接滅燈

7.2 領取範圍／讀取範圍（硬性 · 省 token）

Subagent 只處理自己領取的那一張卡；禁止為「了解全貌」讀完整看板或其他卡。

角色可讀禁止
母對話派工只把該卡欄位與路徑寫進 Task prompt叫子代理打開整份 PROJECT-BOARD.html、掃全部 reports/dispatch-pd/*
實作 AgentPrompt 摘錄；reports/dispatch-pd/<本卡ID>.md；允許路徑內檔案其他 PD-* 報告／無關 crate；整板 Grep；整檔重寫看板
TDD Agent佇列內各卡報告＋對應測試；寫 <ID>-TDD-REVIEW.md一次載入全部工項備註當上下文

看板回寫：只追加本卡短註（或 board.py report）；禁止用過期整份 HTML 覆寫板面殼。

7.3 PM Agent 必作事項（硬性 · 已拍板）

母對話／PM Agent 使用看板工具時下列為必作（細節：tools/board/PM-AGENT.md）：

#必作不合格
