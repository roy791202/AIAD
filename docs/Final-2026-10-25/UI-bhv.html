1. 系統定位

SGGenAxis 的 UI System 是一套可由使用者編輯、可被資料模型描述、可由 AI 協助生成，並可透過驗證流程檢查的 UI 定義系統。

核心原則： UI Layer 負責在架構畫布上代表 UI 系統； Editor 負責編輯 UI； Viewer 負責預覽與操作 UI。 UI 元件的視覺呈現、事件、邏輯、資料綁定與資源參照應由同一份 Canonical UI Definition 管理。

1.1 設計目標

  • 將 UI 架構與 UI 內部元件編輯分離。
  • 讓使用者可以調整結構、配色、樣式及圖片資源。
  • 支援 UI 事件、邏輯節點及資料綁定。
  • 使用穩定 ID 管理節點、Slot、資源與資料參照。
  • 提供 AI 生成、規格檢查、測試與版本追蹤的基礎。

2. UI 架構與操作入口

2.1 Architecture Canvas

主架構畫布只呈現 UI Layer 作為架構節點，不應將 Button、Label、Dropdown 等所有 UI 元件直接散佈在主架構畫布上。

Architecture Canvas └── UI Layer ├── Open Editor │ ├── UI Structure Editor │ ├── Style & Theme Editor │ ├── Asset / Resource Manager │ ├── Event & Logic Editor │ ├── Data Binding Editor │ ├── Inspector │ ├── Validation │ └── Preview └── Open Viewer └── Preview / Runtime Interaction

2.2 UI Layer 屬性

屬性型別用途
uiLayerIdStable IDUI Layer 唯一識別碼。
nameString顯示名稱。
rootNodeIdNode IDUI 結構根節點。
uiDefinitionRefReferenceCanonical UI Definition 參照。
themeRefTheme ID預設主題參照。
assetRefsAsset ID[]此 UI 使用的資源。
schemaVersionVersionUI 定義版本。

2.3 操作入口

  • 選取 UI Layer → Open Editor：開啟該 UI Layer 的編輯環境。
  • 選取 UI Layer → Open Viewer：開啟該 UI Layer 的預覽環境。
  • Window → UI Editor：開啟 Editor，再選擇既有 UI Layer 或建立新 UI Layer。
  • Window → UI Viewer：開啟 Viewer，再選擇要預覽的 UI 定義。

3. Editor 編輯環境

原本的 Edit Logic (UX) 統一更名為 Editor。因為此環境不只編輯邏輯，也負責 UI 結構、配色、樣式、圖檔資源、事件與資料綁定。

Validation檢查結構、屬性、資源、事件、邏輯與資料綁定。Validation Report

4. Viewer 預覽環境

Viewer 用來查看 UI 的實際呈現與互動結果。Viewer 不負責修改 UI 結構、樣式或資源定義。

功能說明
Render UI根據 UI Definition、Theme、Assets 與資料狀態呈現 UI。
Interactive Preview測試按鈕、選單、輸入欄位、切換及其他互動。
Test Data使用模擬資料測試 Data Binding。
Event Inspection在除錯模式下檢視事件是否觸發。
Logic Trace檢視邏輯流程與命令執行結果。
Responsive Preview測試不同視窗尺寸與支援的縮放模式。
Runtime Diagnostics顯示資源載入錯誤、綁定錯誤及執行期警告。
Editor 的 Preview 可以用於快速設計驗證；Viewer 則是獨立的預覽／互動入口。兩者可以共用同一個呈現引擎，但應明確區分編輯權限與執行狀態。

5. UI 節點與 Slot

5.1 Node Hierarchy

UI 元件以樹狀結構組織。允許包含子元件的節點，必須透過 Slot 定義可接受的子節點與容納限制。

Window └── ContentSlot └── Panel ├── HeaderSlot │ └── Label └── BodySlot ├── Input └── Button

5.2 Slot Schema

欄位用途
slotIdSlot 穩定識別碼。
ownerNodeId擁有此 Slot 的父節點。
nameSlot 名稱。
allowedChildKinds允許的子節點類型。
minChildren最少子節點數。
maxChildren最多子節點數；可為無上限。
layoutModeSlot 內的排列模式。
constraints其他結構與尺寸限制。

5.3 子節點關係

  • 每個子節點以 parentNodeId 指向父節點。
  • 每個子節點以 parentSlotId 指向所屬 Slot。
  • 使用 order 記錄同一 Slot 內的排列順序。
  • 不得形成父子循環或孤立的非法關係。
  • 拖放前後均應檢查 Slot 相容性與 Cardinality。

8.3 樣式優先順序

建議採用可預測的樣式合併規則：

Runtime Appearance = Theme Defaults + Component Kind Defaults + Shared Style Reference + Node-Level Overrides + Runtime State Styles

實際優先順序應固定並文件化。若使用者修改共用 Theme，系統應能識別受影響元件，並提示預覽與驗證。

9. Asset / Resource Manager

SVG、PNG、JPG/JPEG、WebP、GIF 等圖檔都統一透過 Asset / Resource Manager 匯入與管理。UI 節點不應直接依賴容易失效的暫存路徑。

9.1 支援的資源類型

格式常見用途注意事項
SVGIcon、Logo、可縮放向量圖。匯入時應限制 Script、外部資源引用與不受信任的內容。
PNG透明背景圖片、圖示、介面貼圖。檢查尺寸、色彩資訊與透明通道。
JPG / JPEG照片、背景及不需透明通道的圖片。有損壓縮；不保留透明通道。
WebP較小體積的點陣圖片，可依編碼支援透明或動畫。依實際解碼器能力確認格式支援。
GIF簡單動畫或相容性需求。動畫播放、色彩與透明處理取決於 Runtime 支援。
Font文字字型資源。檢查授權、格式與字型載入政策。
Other未來可擴充的資源類型。必須先由 Asset Type Registry 宣告處理方式。

9.2 Asset Schema

欄位用途
assetId資源穩定識別碼。
name資源顯示名稱。
assetTypeImage、Vector、Font、Animation 等類型。
formatSVG、PNG、JPEG、WebP、GIF 等格式。
sourcePath原始檔案位置；僅供來源追蹤。
importedPath匯入後由系統管理的資源位置或 URI。
contentHash內容雜湊，用於變更偵測及重複資源判斷。
metadata尺寸、色彩通道、動畫影格數、MIME type 等。
usageRefs引用此資源的 UI 節點與屬性。
importStatusPending、Imported、Warning、Failed、Missing。
licenseInfo授權或來源備註（如適用）。

9.3 Asset Manager 功能

  • Import：匯入一個或多個資源。
  • Preview：顯示縮圖、尺寸、格式及相關中繼資料。
  • Replace：替換資源內容，並檢查引用相容性。
  • Relink：重新指定遺失的來源或資源位置。
  • Find Usage：查找哪些 UI 節點正在使用資源。
  • Duplicate Detection：依內容雜湊或規則識別重複資源。
  • Remove：移除未使用資源，或先提示受影響的引用。
  • Validate：檢查資源遺失、格式不支援及匯入失敗。

9.4 UI 節點與資源的關係

UI Node └── properties.iconAssetId └── Asset Registry ├── assetId ├── assetType ├── importedPath ├── metadata └── importStatus
重要：UI 節點應儲存 assetId，而不是將原始檔案路徑當成唯一識別。當檔案搬移、重新匯入或替換時，系統才能維持引用穩定並追蹤受影響元件。

10. Event System

事件定義應採用結構化資料，而非只將觸發條件寫成自由文字。事件觸發後可以連接 UI Logic、Command 或資料更新流程。

10.1 Trigger 類型

分類事件範例
PointerClick、DoubleClick、MouseDown、MouseUp、MouseMove。
KeyboardKeyDown、KeyUp、ShortcutActivated。
InputValueChanged、TextChanged、SelectionChanged、Submitted。
FocusFocusIn、FocusOut、Activated。
Drag & DropDragStarted、DragMoved、DropEntered、DropAccepted、DropRejected。
LifecycleCreated、Mounted、Shown、Hidden、Disposed。
DataDataLoaded、DataUpdated、BindingFailed。
Custom使用者定義的具名事件。

10.2 Trigger Schema

欄位用途
eventId事件定義 ID。
sourceNodeId事件來源 UI 節點。
eventType事件種類。
modifiersCtrl、Shift、Alt、Meta 等修飾鍵。
mouseButtonLeft、Middle、Right 等滑鼠按鍵。
scopeLocal、Parent、Global 或指定範圍。

10.3 複合觸發範例

例如 Ctrl + Shift + 滑鼠左鍵按下，應拆成可驗證的欄位，而不是只存成一段字串：

eventType: MouseDown modifiers: [Ctrl, Shift] mouseButton: Left scope: Local phase: Target

10.4 Event Output

依元件種類定義可用輸出，例如 onTriggered、onClicked、onChanged、onSubmitted、onSelectionChanged、onDropAccepted。系統應驗證事件與元件種類是否相容。

11. UI Logic

UI Logic 是 Editor 內的邏輯編輯模組。它負責描述事件觸發後的處理流程，不取代 UI Structure、Style 或 Asset 管理。

11.1 Logic Node 類型

Logic Node用途
Start / Event Input接收事件觸發。
SetProperty修改目標節點屬性。
GetProperty讀取節點或資料屬性。
Condition判斷布林條件。
Branch依條件選擇流程分支。
Sequence依定義順序執行多個步驟。
Delay延遲執行；須受 Runtime 執行政策限制。
EmitEvent發送自訂事件。
CallCommand呼叫已註冊的命令。
MapData轉換或映射資料。
Validate執行資料或狀態驗證。
TryCatch處理允許捕捉的執行錯誤。
Return / End結束流程並輸出結果。

11.2 Logic Flow 範例

使用者點擊設定按鈕後顯示 Settings Window：

Button.onTriggered ↓ SetProperty targetNodeId: SettingsWindow property: visible value: true

欄位用途

inputPorts輸入資料與執行介面。

executionPolicy執行時機、重複執行與取消規則。
errorPolicy錯誤處理政策。

邏輯連線必須檢查資料型別、執行流程、循環及無效參照。涉及非同步作業時，需明確定義取消、錯誤與完成事件。

12. Data Binding

Data Binding 連接資料來源與 UI 元件屬性，讓 UI 可以讀取資料並依更新政策同步顯示。資料綁定與事件邏輯應分開建模，但可互相引用。

12.1 Binding Schema

欄位用途
bindingId綁定 ID。
sourceRef資料來源參照。
sourcePath資料來源欄位路徑。
targetNodeId目標 UI 節點。
targetProperty目標屬性，例如 value、text、visible。
directionOneWay、TwoWay、OneTime。
valueType預期資料型別。
conversionRule必要時進行型別轉換。
updatePolicy即時、事件觸發、手動或批次更新。
fallbackValue來源缺值時的預設值。
validationPolicy值域與格式驗證政策。
errorPolicy綁定失敗時的處理方式。

12.2 綁定方向

  • OneWay：資料來源更新 UI。
  • TwoWay：依定義同步 UI 與資料來源；須防止更新迴圈。
  • OneTime：初始化或指定時機讀取一次。

12.3 驗證規則

  • 來源與目標參照必須存在。
  • 來源型別必須能與目標屬性相容，或有明確轉換規則。
  • TwoWay 綁定必須確認目標屬性可寫入。
  • 更新循環須有明確的防護機制。
  • 缺值、錯誤與延遲更新行為必須可設定或採用明確預設。

13. Inspector / Property Schema

Inspector 應依選取節點的 uiKind 動態載入專屬 Property Schema。不要為所有元件固定顯示相同欄位。

13.1 Inspector 頁籤

頁籤顯示內容
General名稱、類型、可見性、啟用狀態、無障礙屬性。
Layout尺寸、間距、對齊、定位及父 Slot 限制。
Style顏色、字型、邊框、陰影、狀態樣式與 Theme 參照。
Assets圖檔、Icon、Font 及其他資源參照。
Events & Logic事件來源、觸發條件、邏輯圖與命令參照。
Data Binding資料來源、目標屬性、方向、更新政策與錯誤處理。
AccessibilityAccessible Name、Role、Description 及鍵盤操作資訊。
AdvancedMetadata、擴充屬性、版本與診斷資訊。

13.2 Property Schema 建議欄位

欄位用途
propertyKey穩定屬性識別碼。
displayNameInspector 顯示名稱。
valueTypeString、Boolean、Number、Color、Enum、AssetRef 等。
defaultValue預設值。
constraints最小值、最大值、格式或允許值。
visibleWhen欄位顯示條件。
enabledWhen欄位可編輯條件。
editorKind適用的屬性編輯器。
validationRules欄位驗證規則。
affects此屬性可能影響的模組或產物。

13.3 動態顯示範例

  • 選取 Button：顯示文字、Icon、Variant、Disabled、Click Event。
  • 選取 Image：顯示 Asset、Fit Mode、Aspect Ratio、Fallback Asset。
  • 選取 TextInput：顯示 Value、Placeholder、Max Length、Input Mode、Validation。
  • 選取 Viewport3D：顯示 Scene、Camera、Navigation Mode、Render Mode。

14. Validation

Validation 應是可重複執行的規格檢查流程，而不是只顯示一個通過／失敗圖示。

14.1 驗證範圍

檢查類別檢查項目
IdentityNode ID、Slot ID、Asset ID、Binding ID 是否唯一且有效。
Hierarchy根節點、父子關係、Slot 歸屬及循環。
Slot子節點類型、最小數量、最大數量與容器限制。
Properties必要屬性、型別、範圍與 Enum 值。
StyleTheme 參照、樣式型別、缺失 Token 及不相容設定。
Assets資源是否存在、格式是否受支援、匯入狀態與引用是否有效。
Events事件種類、觸發欄位與來源元件是否相容。
Logic連線型別、必要輸入、無效參照、不可達流程及循環政策。
Binding來源、目標、資料型別、寫入權限與更新循環。
Accessibility必要標籤、角色與鍵盤操作支援。
Version規格變更後，相關測試與產物是否仍然有效。

14.2 驗證狀態

狀態意義
Valid已通過目前所執行的檢查。
Warning存在非阻斷性問題或建議改善事項。
Invalid存在阻斷性錯誤，需修正後才能通過。
Stale依賴規格或來源已變更，舊驗證結果不再能代表目前版本。
NotValidated尚未執行驗證。

14.3 變更與失效追蹤

UI 結構、Style、Asset、Event、Logic 或 Binding 改變時，系統應依依賴關係標記受影響的驗證結果、BDD / TDD、預覽快取與生成產物為 Stale。只有重新執行相應檢查後，才可更新驗證狀態。

AI 不應在缺少必要規格或遇到互相矛盾的設定時自行猜測核心行為。應回報缺項、指出衝突，並在已定義的限制內提出修正方案。

15. Canonical UI Data Model

Architecture Canvas、Editor、Viewer、Inspector、AI 與 Validation 應使用一致的 UI 定義及 ID 參照。各畫面可以有自己的視圖狀態，但不能各自維護互相矛盾的元件定義。

15.1 核心資料集合

UI Definition ├── UI Layer Reference ├── Root Node ID ├── UI Nodes[] │ ├── Properties │ ├── Slot Definitions[] │ ├── Style Reference │ ├── Asset References[] │ ├── Event References[] │ └── Binding References[] ├── Component Definitions[] ├── Theme Definitions[] ├── Style Definitions[] ├── Asset Registry[] ├── Event Definitions[] ├── Logic Graphs[] ├── Data Bindings[] ├── Validation Reports[] └── Version / Dependency Metadata

15.2 UI Definition Schema

欄位用途
uiDefinitionIdUI 定義唯一 ID。
schemaVersion資料結構版本。
rootNodeIdUI 根節點。
nodesUI 節點集合。
components可重用元件定義。
themes主題集合。
styles樣式集合。
assets資源登錄表或其參照。
events事件定義。
logicGraphs邏輯圖定義。
bindings資料綁定定義。
bddRefs / tddRefs行為需求及測試案例參照。
validationStatus最近一次驗證結果。
dependencyRefs外部資料、命令或其他模組的依賴參照。

15.3 關注點分離

  • UI Definition：描述 UI 是什麼。
  • Architecture Assignment：描述 UI Layer 在架構中的歸屬與依賴。
  • Editor Workspace State：描述面板、選取狀態與工作區佈局。
  • Viewer Runtime State：描述預覽或執行時的暫態狀態。
  • Asset Registry：描述資源身分、匯入位置及使用關係。
  • Validation Report：描述指定版本、指定檢查範圍的驗證證據。

16. 操作流程

16.1 建立與編輯 UI

Create / Select UI Layer ↓ Open Editor ↓ Create / Edit UI Structure ↓ Configure Slots & Properties ↓ Edit Style & Theme ↓ Import / Assign Assets ↓ Configure Events & Logic ↓ Configure Data Bindings ↓ Validate ↓ Preview in Viewer ↓ Save Version

16.2 修改既有資源

Select Asset ↓ Inspect Metadata & Usage References ↓ Replace / Relink / Edit Import Settings ↓ Check Referencing UI Nodes ↓ Revalidate ↓ Refresh Preview

16.3 UI 修改後的依賴追蹤

當元件結構、樣式、事件、資源或資料綁定發生變更時，系統應透過依賴關係找出受影響項目，避免只更新畫面而遺漏規格與測試。

17. 實作優先順序

階段建議交付項目完成條件
P0 — 資料骨架UI Definition、Node Schema、UI Kind Registry、Slot Schema、穩定 ID。可建立、儲存與載入合法的 UI 樹。
P1 — Structure Editor元件新增、刪除、複製、拖放、Slot 驗證。結構變更可持續保存且不產生非法層級。
P2 — Style & Theme配色、字型、尺寸、狀態樣式、Theme 參照。樣式可重用，並能在預覽中正確呈現。
P3 — Asset Manager匯入、預覽、替換、Relink、Usage Reference。資源以穩定 ID 引用，遺失資源可被檢出。
P4 — ViewerUI 呈現、互動預覽、模擬資料、執行期診斷。可在隔離的預覽環境測試 UI。
P5 — Event & Logic事件定義、Logic Graph、型別與執行流程檢查。互動流程可重現並能追蹤錯誤。
P6 — Data Binding來源與目標參照、更新政策、型別轉換、錯誤處理。綁定錯誤與更新循環可被識別。
P7 — Validation / Testing完整驗證、BDD / TDD 關聯、Stale 追蹤。驗證結果可追溯至明確版本與證據。
P8 — AI Integration依 Schema 生成 UI、資源指派建議、事件與綁定生成。AI 輸出先經結構驗證，不直接宣告成功。

最終設計原則

SGGenAxis UI System 應將 UI 結構、視覺樣式、資源、事件、邏輯、資料綁定與執行狀態分開建模，再透過穩定 ID 與明確依賴關係整合。Editor 提供統一編輯入口，Viewer 提供獨立預覽入口；兩者共用同一份 Canonical UI Definition，以支援可擴充的元件系統、AI 輔助生成與可驗證的開發流程。
