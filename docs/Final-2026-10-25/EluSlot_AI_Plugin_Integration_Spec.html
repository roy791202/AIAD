01｜接入方向與架構判斷

建議提供 EluSlot 官方 Plugin 接入套件，讓使用者在既有 AI 工具中領取、執行與回報工項，降低手動設定與重複說明成本。

核心工作流程保持不變：規劃（架構／UI）→ Tasks → 外部 AI 執行 → 驗證／接受 → 檔案更新／Git。Plugin 是安裝與接入入口，後端仍掌管資料、狀態與授權。

可安裝 Plugin，不代表能控制整個宿主

Skill 與 MCP 可提供工作規則與工具，但主動排程、模型選擇、子代理限制、完整用量與程序停止，都必須依宿主與版本逐項驗證。

本文是設計規格，不是已發佈 Plugin，也不是已驗證的跨宿主能力承諾。查核日期：2026-10-26。

02｜接入套件的組成

部分責任不能取代
Skill／Workflow教 AI 如何領取、讀引用、實作、測試、回報與受阻權限與資源硬限制
MCP／API 工具提供工作包、補取上下文、進度、問題與結果提交產品派工與驗收規則
連接設定服務位置、專案身分、驗證與權限持續可用的後端服務
Runner／宿主配接器輪詢、心跳、重試、取消與可支援的資源控制服務端的權威狀態
EluSlot 後端管理 XML／規劃、Task／Run、引用、驗證與 LogAI 實際工作環境與工具

以共用核心契約服務不同宿主，分開維護包裝與配接設定。不要假設 Codex 與 Claude 的 manifest、hooks 或設定檔可以原封不動互換；共用的是業務規則、工作包與 API 語意。

03｜使用者首次接入流程

步驟使用者系統
安裝選擇對應宿主的 EluSlot Plugin載入規則、工具連接與版本資訊
連接選服務與專案，完成授權驗證身分、權限與協定／契約相容性
檢查指定程式碼工作目錄檢查工具、可讀寫範圍、Git 與產出交付位置
確認模式選擇手動領取或自動輪詢顯示支援能力及不能強制的限制
試跑執行內建驗證工項完成領取、測試、提交、產出取得與驗收
日常工作在 EluSlot 規劃、派工與接受組裝上下文，追蹤執行與異常

不要求使用者每次貼上專案背景。任務內容由系統依 BDD、引用、規劃與程式碼基準組裝。首次授權與必要歧義仍需使用者處理。

本機桌面服務、區網服務與遠端服務需分開處理可達性；雲端宿主的 localhost 不是使用者電腦。連線測試必須從真正的執行端進行，不為接入而默認公開本機服務。

04｜AI 如何知道規則與資料格式

  1. 已知入口：Plugin 提供工具定義、驗證方式與精簡 Workflow。
  2. 能力與版本檢查：確認後端支援契約、專案權限與宿主配接能力。
  3. 取得工項：讀取或領取工作，領取由後端原子處理。
  4. 讀工作包：取得目標、BDD、引用、修改範圍、版本、驗收與資源政策。
  5. 按需補取：以穩定 ID 讀取必要依賴，保存所用版本。
  6. 執行回報：追加進度、問題、差異、測試與產出，不直接改專案 XML。
工具類型（概念名稱）用途
檢查連接／能力確認版本、身分、權限與可強制限制
查詢／領取工項區分閱讀與執行擁有權，回傳 Run 與租約
讀取引用／上下文取得節點、UI、介面與版本化資料
回報進度／問題追加 Log；資訊不足時轉為待確認
提交產出／結果提交可取得的差異、報告與雜湊
查詢取消／執行狀態讓 Runner 檢查是否應停止或恢復

以上是建議工具語意，不是定稿路由。Schema 說明參數格式，Workflow 說明使用順序，工作包提供當次需求；三者不可互相替代。

05｜手動協作與自動執行

模式啟動方式適用／限制
對話式 Plugin使用者要求領取或查看工項容易接入；不能假定對話結束後仍持續工作
宿主支援的自動化使用宿主實際提供的排程／背景能力需驗證生命週期、睡眠、關閉與權限行為
獨立 Runner常駐程式或排程器輪詢並啟動 Agent適合五分鐘輪詢與可靠恢復，需維護部署環境
輪詢與心跳由程序維持

閒置查詢不必呼叫模型。領取後才啟動 AI；執行中的續租由 Runner 管理，不依賴模型記得定時回報。只有工具與 Skill 的 Plugin 不等於永久常駐服務。

第一版先完成手動領取的完整閉環，再接獨立 Runner。若宿主已能可靠提供所需背景能力，可用配接器重用，但不把它當作跨產品的共同保證。

06｜宿主能力驗證矩陣

能力需驗證的行為缺少時的處理
工具／Schema工具可探索、參數有效、錯誤可判讀不宣告可用；提供支援的 API／SDK 路徑
排程／背景五分鐘執行、關閉／睡眠與恢復改由外部 Runner，或僅手動
模型與推理指定值是否實際生效、是否有內部路由標示未知／不可強制，不承諾上限
子代理能否禁止、限制等級、累計數與遞迴限制自動模式，或使用受控執行環境
完整用量主／子代理、失敗／重試用量可取得顯示估算或不可見，不能假精準
取消與檢查點能否停止程序樹、保存成果與確認停止標記取消請求／未知，不假稱已停止
工作目錄與交付可讀寫範圍、隔離與產出上傳阻止需要此能力的派工
身分與版本穩定執行者識別、契約版本與設定相容要求重新授權／升級，不靜默放寬限制

每個能力保存「已驗證支援、僅指引、不支援、未知」及測試版本。這是待測清單，不是宣稱兩種宿主已具備全部能力。更新 Plugin 或宿主後，重新檢查關鍵能力。

07｜政策、身分與追蹤

控制層責任
專案政策最高模型權限、預算與禁止範圍
燈號預設依工作階段帶入預設執行配置
Task／批次個別限制與相容配置；無合規配置就拆批或受阻
Runner依能力強制執行，不能只向模型口頭要求
後端領取、狀態、版本、引用權限與接受規則

子代理與重試共享總預算，換燈與新 Run 不重置消耗。橘燈等待測試不維持模型空轉；紅燈複雜診斷才依政策使用較強模型。單次工具呼叫成功不等於 Task 完成。

身份由憑證確認，Log 區分使用者、Agent／Runner 與委派者。記錄誰讀取、領取、提交、驗證、接受與交付，串接 Task／Run／Request ID、版本與產出。敏感憑證不進 Log，也不放入工作包。

工具只開放需要的操作；工作資料或外部文件中的指令不能擴大授權。Skill、hooks 與 SDK 限制仍須以實際可攔截路徑檢查，不宣稱能控制宿主所有隱藏行為。

08｜有 Git／無 Git 與服務可用性

面向共同規則／差異
共同工作包BDD、Task 引用、基準與模型政策相同
無 Git以文件版本、快照、檔案雜湊與結果包交付
有 Git附基準與可取得的 patch／Commit；提交與 Push 另行處理
產出取得Agent 本機路徑或孤立 SHA 不代表後端可取得產出
服務中斷暫停新派工、退避、保存待回報事件；恢復後去重補傳
租約過期舊持有者不得更新權威狀態或自動套用結果
桌面關閉若服務依附桌面程序則停止；需要持續運作就部署獨立服務
版本更新工作包／API／Plugin 分別記版本，破壞性更新不可靜默套用

09｜待驗收清單與導入順序

以下 12 項是產品待執行驗收規格，不是 Plugin 實測結果。

案例類型情境通過條件
P01正常安裝與連接可確認專案、身分、版本與工具。
P02正常手動領取並提交Run、Log 與可取得產出完整；提交不等於接受。
P03正常五分鐘輪詢無工項時不啟動模型，有工項才領取執行。
P04邊界兩個宿主同時領取後端只授予一個有效持有者。
P05邊界能力不支援強制模型上限明確顯示不支援，阻止要求硬限制的自動模式。
P06無效錯誤憑證或跨專案引用拒絕存取，不外洩內容。
P07無效API／Plugin 契約不相容提出升級或停止，不猜格式繼續寫入。
P08失敗API 中斷與回報重送可補傳且不重複事件或套用。
P09失敗取消後仍有外部程序顯示未確認停止，不能假稱取消完成。
P10失敗租約過期後舊結果回來拒絕舊世代的權威寫入。
P11相容有 Git／無 Git 試跑都能驗收與取得交付內容。
P12部署雲端宿主連本機地址可達性檢查失敗時清楚說明，不默認公開服務。
  1. 固定後端工作包、工具契約與服務端規則。
  2. 選一個明確宿主版本，提供 Skill＋工具接入並完成手動試跑。
  3. 建立第二宿主包裝，驗證共用契約，不複製派工邏輯。
  4. 加入 Runner 自動化、能力矩陣與受控資源政策。
  5. 依實測需求增加背景能力、升級與發布維護。

驗收底線：使用者連接一次後，不需每次重貼規劃即可領取執行；限制能力如實揭露；每個結果可追溯到版本與執行者。不中斷必要驗證以換取表面上的自動化。
