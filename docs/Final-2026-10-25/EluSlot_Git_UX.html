版本與能力探測

請求契約（提案）

{
  "requestId": "req-unique",
  "operation": "git.file.stage",
  "repoId": "host-resolved-repo",
  "expectedRepoVersion": 17,
  "payload": { "paths": ["src/git.ts"] },
  "reviewToken": "prepared-scope-token"
}

prepare → reviewToken → execute。Token 綁 repo、operation、payload、HEAD、Index tree；檔案覆寫操作另綁內容 hash。核對後狀態改變必須重新檢視。

結果與事件（提案）

{
  "requestId": "req-unique",
  "status": "success | error | cancelled",
  "repoVersion": 18,
  "data": {},
  "error": { "code": "INDEX_CHANGED",
             "retry": "prepare-again" }
}

事件 started → progress → completed。以 exit code＋狀態重讀判斷結果；取消、timeout 與網路中斷可能有部分完成。不可只看 stdout。

提交分支圖串接（Git → Graph Model → SVG）

Git log 以 topo-order 輸出完整 OID、所有 parent OID、作者、時間與摘要；for-each-ref 提供 local／remote／tag 標籤。解析結果建立 DAG，再做穩定的泳道分配與邊路由；row 與 node 共用選取 ID。不要用日期推測父子，不從 lane 顏色推論某 commit 永久屬於某 branch。

多 parent 為 Merge；同一 parent 被多個已載入 child 引用即顯示分岔。Parent 1／2 可分別比較，父提交不在已載入範圍時呈現邊界或載入更多，不假造根節點。正式版需另驗證分頁、shallow、octopus merge 與大量 refs。窄視窗保留節點與文字大小並水平捲動，不縮成看不清楚的圖。

衝突狀態投影（Host → UI）

{ operation: { kind: "merge | rebase", phase: "blocked | ready | completed | aborted", sourceOid, targetOid },
  conflicts: [{ path, gitStatus: "UU | AA | ...", stages: [1,2,3],
                resolution: "unresolved | editing | resolved", draftVersion, savedVersion }],
  unmergedFileCount, pendingDraftCount, canContinue, repositoryVersion }

Host 重新讀取操作 metadata 與 unmerged entries；UI 的「編輯中」是尚未存檔的草稿狀態。「已解決」需原子存檔與 add 成功後重讀確認。canContinue 同時檢查 unmergedFileCount=0、pendingDraftCount=0 與合法的 operation。重新編輯已解決檔案立即停用繼續；失敗維持編輯狀態。全域提醒、側欄數字、檔案列與 footer 都使用同份快照。

實作約束與可觀測性

  • Git 2.30+ 為設計基準，Host 啟動探測版本。指令佔位符不是可複製 shell 腳本；用 argv 陣列及 stdin，不拼接 shell。
  • 檔名使用 NUL-safe 格式及 literal pathspec；revision 先解析完整 OID；branch、remote、URL 分別驗證以避免選項注入。
  • hooks、簽章、askpass 與 editor 仍會由 Git 啟動；需桌面橋接，不能因 shell=false 就宣稱無其他程序。
  • 每個 repository 一條寫入 queue；完成後發 repositoryChanged 並刷新受影響快照，所有視窗共享版本。
  • 記錄 requestId、operation、duration、exit code、錯誤分類與刷新結果；不記憑證、敏感 URL 或完整提交草稿。
  • 本版不包含 Git 工作台、PR 託管服務、互動 Rebase squash、LFS／submodule 管理、遠端 branch/tag 刪除；偵測到不支援狀態必須明示，不能假裝完整支援。

測試與驗收

只驗證此 HTML 與操作登錄表，不代表已測試真實 Git。

本文件驗證紀錄

JavaScript 語法檢查、65 項 UI 路由與契約結構檢查，以及 39 項離線 DOM 互動測試。瀏覽器預覽受環境限制，未完成實際瀏覽器截圖、視覺與焦點驗證；未執行真實 Git 整合測試。

正式串接的驗收條件

  1. 65 項操作各有唯一 UI ID、真實入口、API、前置條件、Git／Host 責任、結果刷新與錯誤回復。
  2. 臨時 repo＋本地 bare remote 驗證操作；兩份 clone 驗證 divergence、衝突與 lease mismatch。
  3. 外部 Index／HEAD／檔案改動使 reviewToken 失效；所有 Git 視窗刷新至同版快照。
  4. Unicode／換行／空白／選項型檔名、CRLF、rename、binary、unborn、detached、worktree 佔用均有測試。
  5. 提交失敗保留草稿；未解衝突不能繼續；non-fast-forward 不自動 force；timeout 重試前核對結果。
  6. 鍵盤可完成主要流程；焦點可見、Escape 關閉、Modal 焦點回原入口；窄視窗內容可閱讀。

本文件中的案例是測試規格；結構檢查通過不等於上述 Git 整合測試已通過。

使用指引與官方參考

  1. 在「互動介面」切換情境，操作檔案、提交、分支、Stash 與衝突。
  2. 開啟「串接檢視模式」，點 Git 控制項可看完整契約；不變更模擬資料。
  3. 「功能 × UI × Git」搜尋任意功能；「前往 UI」會定位入口，必要時切換示意情境。
  4. 視窗可注入錯誤測試回饋；提交確認另有「核對後狀態改變」測試。
  5. 匯出 JSON 可轉成開發任務與 API 規格；列印包含功能表、架構、流程與驗收。

原型只示範主要狀態轉移；簡化的 Diff、歷史與遠端不是完整 Git 模擬器。正式版 UI 由真實 Git 結果驅動，不可直接把此頁模擬邏輯接到使用者專案。
