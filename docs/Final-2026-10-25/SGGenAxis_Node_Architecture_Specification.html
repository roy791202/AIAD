文件目的

統整 SGGenAxis 節點架構的建議資料模型，供 UI 設計、資料結構規劃、AI 生成與驗證流程使用。

核心原則：Node Definition 定義節點是什麼；Architecture Assignment 定義節點屬於哪裡；UI Layout 定義節點在畫布上如何呈現。三者分離，避免畫面變更影響業務規格。

1. 核心架構概念

SGGenAxis 建議採用共用 Node 基礎結構，再由不同 Node Type 定義專屬屬性、驗證規則與 AI 生成行為。BDD / TDD 是結構化規格，不應只存成自由文字。

層級責任建議規則
Layer技術架構層級與依賴方向定義允許的 Node Type、依賴限制與 Layer 對外介面
Module SlotLayer 內的模組分組容器可獨立展開／收合；可接收或移出 Node
Node具體責任單位有專屬屬性、Input / Output、BDD / TDD 與依賴
Module Registry模組的穩定定義Module ID 與顯示名稱分離；可供跨 Layer 參照

畫布行為

  • Layer 內可有多個 Module Slot。
  • 每個 Module Slot 可獨立展開／收合。
  • Module 展開後，Node 以水平方式排列。
  • Node 卡片只保留左側 Input、右側 Output。
  • Layer、Module Slot、Node 的 Input / Output 是不同層級的介面。
  • 拖曳時應區分「改變歸屬」與「改變畫布位置」。
水平排列只代表視覺佈局，不代表程式執行順序；執行順序由明確連線、依賴與流程規則決定。

3. 十種 Node Type 專屬屬性

以下為建議欄位。實際 Schema 應依 SGGenAxis 支援的語言、執行環境與生成方式調整。

3.1 API Node

  • httpMethod：HTTP 方法
  • route：路由定義
  • requestSchemaRef：Request 結構
  • responseSchemaRef：Response 結構
  • authPolicyRef：驗證／授權政策
  • errorMapping[]：錯誤映射
  • rateLimitPolicy：流量限制（選用）

3.2 Contract Node

  • contractKind：DTO、Event、Interface、Schema 等
  • schemaDefinition：欄位、型別與結構
  • requiredFields[]：必填欄位
  • constraints[]：格式、範圍、唯一性限制
  • compatibilityPolicy：版本相容策略
  • contractVersion：契約版本

3.3 UI Node

  • componentType：Page、Form、Panel、Dialog 等
  • layoutSpec：版面配置
  • dataBindings[]：資料綁定
  • actions[]：操作與事件
  • stateDefinition[]：狀態與轉換
  • validationRules[]：表單驗證
  • accessibilitySpec：無障礙需求

3.4 Command Node

  • commandName：命令名稱
  • inputSchemaRef：輸入結構
  • preconditions[]：執行前條件
  • effects[]：預期狀態變更
  • transactionPolicy：交易邊界與原子性
  • idempotencyPolicy：重複執行策略
  • failurePolicy：失敗、重試與補償策略

3.5 Query Node

  • queryName：查詢名稱
  • sourceRefs[]：查詢來源
  • filterSchema：篩選條件
  • sortRules[]：排序規則
  • paginationPolicy：分頁方式
  • projectionSchemaRef：回傳欄位結構
  • consistencyPolicy：一致性要求

3.6 Application Node

  • useCaseName：使用案例名稱
  • steps[]：流程步驟
  • orchestrationMode：Sequential、Parallel 等
  • branchRules[]：條件分支
  • timeoutPolicy：逾時策略
  • retryPolicy：重試策略
  • compensationFlow[]：補償流程

3.7 Domain Node

  • domainKind：Entity、Value Object、Aggregate、Domain Service 等
  • properties[]：業務資料與型別
  • invariants[]：必須成立的業務規則
  • domainOperations[]：領域行為
  • domainEvents[]：領域事件
  • identityPolicy：身分與相等性規則
  • lifecycleRules[]：生命週期限制

3.8 Infrastructure Node

  • adapterKind：Database、HTTP Client、Storage、Queue 等
  • implementsRef：實作的介面／Port
  • provider：技術提供者或驅動程式
  • connectionRef：安全連線設定參照
  • mappingRules[]：資料轉換
  • timeoutPolicy：呼叫逾時
  • resiliencePolicy：重試、斷路器等

3.9 ACL Node

  • externalContractRef：外部契約
  • internalContractRef：內部契約
  • translationRules[]：欄位及語意轉換
  • enumMappings[]：枚舉映射
  • errorTranslationRules[]：錯誤轉換
  • versionMappingPolicy：版本相容
  • fallbackPolicy：映射失敗處理

3.10 Custom Node

  • customTypeId：自訂類型 ID
  • schemaRef：自訂屬性 Schema
  • inputSchema[] / outputSchema[]：自訂介面
  • executionHandlerRef：執行處理器參照
  • validationRules[]：自訂驗證規則
  • capabilities[]：能力宣告
  • permissionPolicy：執行權限

4. Input / Output Port 資料結構

Port 不應只是視覺上的圓點，而是可供型別檢查、資料映射、AI 生成與連線驗證使用的結構化定義。

欄位用途
portIdPort 唯一 ID
name顯示名稱
directioninput 或 output
dataType基本型別或自訂型別
schemaRef複雜資料 Schema 參照
required是否必填
cardinality單筆、多筆或串流等基數
constraints[]值域、格式及其他限制
defaultValue可選預設值
errorTypeRefs[]可能輸出的錯誤型別
description用途與語意說明

Layer 與 Module Slot 的 Input / Output

Layer Input / Output 是 Layer 的對外介面；Module Slot Input / Output 是模組的對外契約；Node Input / Output 是節點本身的介面。三者透過明確 mapping 或連線建立，不應自動把所有內部 Port 全部暴露。

5. BDD / TDD 結構

BDD 與 TDD 應為多筆可追蹤的結構化記錄，並以穩定 ID 關聯 Node、Port、Module 與測試證據。

BDD 欄位

欄位用途
bddId唯一 ID
title場景名稱
given[]前置條件／Given
when[]觸發事件／When
then[]可驗證結果／Then
priority優先級
tags[]分類標籤
relatedNodeRefs[]相關 Node
acceptanceStatus待驗收、通過、失敗等

TDD 欄位

欄位用途
tddId唯一 ID
title測試案例名稱
testTypeUnit、Integration、Contract、E2E 等
arrange[]測試準備／Arrange
act[]執行動作／Act
assertions[]預期結果／Assert
relatedBddIds[]覆蓋的 BDD 場景
relatedPortRefs[]驗證的介面
testStatus未執行、通過、失敗、過期等
evidenceRefs[]執行紀錄、報告或產物
範圍原則：Node 層 BDD / TDD 用於局部行為與單元測試；Module 層可定義跨 Node 的整合行為；系統層可定義端到端流程。規格變更後，相關測試應標記為需要重新驗證。

6. Module、Layer 與拖曳行為

操作建議資料變更驗證
Node 拖入 Module設定 moduleRef；Node 出現在該 Module 內Node Type 是否允許、依賴與 Port 相容性
Node 移至另一 Module更新 moduleRef 與佈局順序跨模組依賴、介面與 Layer 規則
Node 拖出 ModulemoduleRef = null 或指向新容器檢查依賴及未分配政策
Module 展開／收合更新 UI Layout 的 collapsed不改變架構關係
Node 排序更新 order；自由畫布可更新 x / y不把視覺順序當成執行順序
Module 改名更新顯示名稱，不改 moduleId關聯維持穩定

Unassigned Nodes

建議提供未分配節點區域。未歸屬 Module 的 Node 可以存在於草稿階段；驗證時依專案政策決定顯示警告或錯誤。拖出 Module 不應直接刪除 Node。

未分配 Node顯示名稱、類型與基本屬性
→
拖入 Module設定 moduleRef，並依水平佈局排列
→
驗證歸屬檢查 Node Type、Ports、依賴與必要規格

7. UI Layout 與座標資料

座標有保存價值，但應放在獨立的 UI Layout／Presentation Model，而不是 Node 的業務定義內。若畫布採自由佈局，保存 x / y；若 Module 內 Node 固定水平排列，優先保存 order。

欄位適用情況說明
nodeLayout.x / y自由畫布保存 Node 在畫布上的位置
nodeLayout.order水平／自動排列保存 Module 內的顯示順序
nodeLayout.width / height可調尺寸節點保存使用者調整後的尺寸
moduleLayout.orderLayer 內多個 Module保存 Module 的排列順序
moduleLayout.x / y自由排列 Module保存 Module 容器的位置
moduleLayout.collapsed可展開／收合 Module保存展開狀態
viewport.zoom / pan畫布檢視狀態可選；保存縮放與視角位置

三類資料分離

資料區塊主要內容
Node DefinitionnodeId、nodeType、Ports、專屬屬性、BDD、TDD
Architecture AssignmentlayerRef、moduleRef、dependencies、歸屬狀態
UI Layoutx、y、order、width、height、collapsed、viewport
如果 Module 內 Node 固定水平排列，通常只需儲存 order；不必把每個 Node 的 x/y 當成主要資料。座標可由佈局引擎依容器大小與排序計算。

9. AI 生成與驗證

欄位用途
generationPolicyAI 可新增、修改或禁止修改的範圍
implementationRef對應檔案、類別、函式或程式碼符號
validationEvidence[]型別檢查、測試、建置等證據參照
specVersion規格版本；規格更新後判斷測試是否過期
validationStatus由驗證器產生，不由 AI 自行宣告成功

AI 行為原則

  • 缺少必要規格時，提出缺項，不猜測核心業務規則。
  • 發現互相矛盾的 BDD、TDD、Ports 或依賴時，回報衝突。
  • 生成後必須經過可重現的驗證程序。
  • 測試通過狀態由測試執行結果更新。
  • 密碼、Token 等機敏資料不應直接放入一般 Node 屬性或提示內容。

10. 實作優先順序

階段建議交付項目
P0 — 資料骨架共用 Node Schema、10 種 Node Type Registry、Layer／Module ID、Port Schema
P1 — 畫布互動拖放、Module 展開／收合、水平排列、Unassigned Nodes、佈局保存
P2 — 規格管理BDD／TDD 編輯器、關聯 ID、規格版本與過期狀態
P3 — 驗證型別相容、依賴規則、循環依賴、必要規格檢查
P4 — AI 整合上下文封裝、生成限制、實作追蹤、測試證據與報告

結論

SGGenAxis 應將 Node 定義、架構歸屬與 UI 佈局分離。Node 類型決定專屬屬性；Layer／Module 決定架構組織；Input／Output 決定介面契約；BDD／TDD 描述與驗證行為；座標與順序只控制畫面呈現。此分離方式有利於修改 UI、擴充 Node Type，以及讓 AI 更可靠地生成與驗證程式。
