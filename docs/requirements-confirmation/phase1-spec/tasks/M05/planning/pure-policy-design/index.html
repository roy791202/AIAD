intent
Evaluate immutable asset retention using explicit complete root projections. Pure eligibility is never authority to physically delete.
confirmed_baseline
  • Single-document merge plus necessary asset/reference changes only
  • Undo cannot delete material still used elsewhere
  • Recovery contains necessary unsaved assets
  • Formal save retains recovery versions until an approved retention policy cleans them
  • M02 C+B pending precision does not block this independent M05 preparation review
architecture
hexagonal
Test/future HOST use case -> WORK evaluate_asset_retention; no output port in this pure slice. Future HOST collects authoritative root projections through separately approved capabilities.
dependencies
M04 history/document owners + M07 retained snapshots + transaction owner provide projections; M05 evaluates them without mutation. No implementation of those providers in S1.
ownership
Owning modules retain SSOT and root lifecycle; RootSnapshot is immutable derived data. Evaluation result has no FS handle, cleanup lease or deletion token.
mutation
None. Inputs borrowed immutably; no IDs allocated, paths resolved or catalog changed.
transaction
None in S1. Physical cleanup still requires separately approved completeness/freshness fencing and durable catalog transaction. Never invoke remove_file based solely on Eligible.
public_boundary_proposed
function
evaluate_asset_retention(candidate: &AssetCandidate, roots: &RootSnapshot, context: &EvaluationContext) -> Result<RetentionDecision, RetentionError>
AssetCandidate
asset_id:String; content_digest:String; owned_by_operation:Option<String>
RootKind
LiveDocuments | UndoHistory | RedoHistory | RecoverySnapshots | InFlightTransactions
RootReference
asset_id:String; content_digest:String; owner_id:String
RootObservation
kind:RootKind; revision:String; completeness:Complete|Unknown; references:Vec<RootReference>
RootSnapshot
project_id:String; session_id:String; observations:Vec<RootObservation>
EvaluationContext
project_id:String; session_id:String; operation_id:String; expected_root_revisions:Vec<(RootKind,String)>
RetentionDecision
Retain { reasons:Vec<RetentionReason> } | EligibleForCleanup { asset_id:String, content_digest:String }
RetentionReason
Referenced{kind,owner_id} | RootsIncomplete{kind} | StaleRoots{kind} | NotOwnedByOperation | IdentityConflict{asset_id}
RetentionError
InvalidInput { field:String, reason:String }
note
Nested Completeness and reason discriminants are data only. New Port, crypto hashing, material cache, catalog persistence, timer and cleanup manager are excluded.
contracts
order
  • Validate nonempty bounded identity strings and digest syntax; reject malformed/duplicate provider kinds or duplicate expected revisions with InvalidInput.
  • Exactly five required root kinds must be explicitly represented. Missing kind, Unknown status or mismatched expected revision produces conservative Retain reason, never complete-empty eligibility.
  • Matching exact asset_id+digest reference retains by root and owner. Same asset_id with an unresolved conflicting digest retains as IdentityConflict; no guessing provenance.
  • Candidate belongs to this operation only when owned_by_operation equals context.operation_id. Otherwise retain as NotOwnedByOperation.
  • EligibleForCleanup only when all five providers are Complete and expected revisions match, no relevant reference/conflict exists and candidate is operation-owned.
identity
root project/session equals context project/session; mismatch is InvalidInput. LiveDocuments contains every project document, not just active document. Session key does not exclude other sessions from root completeness.
output
Reasons deduplicated and sorted by fixed root order LiveDocuments/UndoHistory/RedoHistory/RecoverySnapshots/InFlightTransactions, then reason discriminator and owner_id byte order. Eligible carries identity only; never path or permission.
failure
No input mutation; malformed input errors do not hide root-incomplete state by pretending deletion is allowed.
trust
HOST must obtain honest root completeness. Strings/revision equality alone do not authenticate providers or grant native deletion authority.
