2. 假設與建議預設

assumptions

  • 初始模板只對已採納的Windows11 x64／local desktop／Rust＋Vanilla UI／Tauri2／has_ui=true組合驗證；其他組合明示UnsupportedTarget並保存定義，不偽造支援。

Detailed proposed architecture

architecture

A1_context
作者確認生成預覽；M01提供不可變定義，M02產生計畫與版本，M03僅消費已啟用且驗證的不可變內容，M08另做環境驗收。
A2_hexagonal
UI/Test → Tauri Command → DispatchHost → HOST GenerationUseCase → WORK pure generation policy；HOST → existing FileSystemPort/FileCommitPort + proposed GenerationArtifactPort ← Windows generation-store adapter。
A3_dependency
M01 ProjectDefinition → M02 WORK plan；HOST maps template/approval codecs and renders bytes；Adapters → Ports + existing SPEC hash；WORK不新增serde/SPEC/FS/OS依賴。
A4_responsibility
WORK只驗證欄位與不可變綁定/產物意圖；HOST核實approval來源、模板內容、渲染與發布；adapter獨佔擁有staging並提供受保護讀取快照。
A5_input
  • prepare_generation（唯讀）
  • confirm_generation（明確寫入）
  • cancel_generation（消耗未套用計畫）
  • read_current_generation（唯讀consumer）
A6_output
  • FileSystemPort：已授權根的模板/SPEC bytes讀取，不擴充現有語意
  • FileCommitPort/FileWriteLease：active.json單檔writer lease/read_current/replace_checked
  • GenerationArtifactPort + OwnedGenerationStage + GenerationReadLease：本提案三trait，10方法，公開值均為primitive/opaque bytes
A7_driving
Vanilla UI、公開邊界測試與受控child consumer；本輪未接入。
A8_driven
Windows generation store、本機唯讀template catalog；假Port用於L2 fault injection。
A9_direction
UI不可呼叫FS/Store adapter；Domain無OS/serializer；Host只經Port寫入。新adapter可共享file_commit內部coordination/唯讀journal判斷，不更改公開FileCommit契約。
A10_ownership
M01/WORK仍是專案定義SSOT。C的GenerationPlan為派生值；HOST每專案GenerationSession最多持有1個準備計畫及其渲染bytes。版本目錄是派生產物，active.json僅指定可見版本，不是另一個專案內容SSOT。
A11_mutation
只有核准HOST confirm用例可在固定受管區建立版本和替換active。prepare/cancel未確認計畫不寫FS；reader不清理、不恢復、不寫檔。
A12_transaction
唯讀prepare → 使用者確認 → initialize namespace → acquire active writer lease → recheck binding → stage/write/verify → seal不可變版本 → 再查定義/approval → FileCommit替換active → receipt；失敗保留舊active或回RecoveryRequired。不是跨檔原子交易。
A13_external
本機經HOST授權project root；所有relative artifact路徑驗證，拒絕reparse/hard-link/不確定別名；未知marker/版本/檔案不自動接管或刪除。
A14_forbidden
  • 逐檔覆寫當多檔原子
  • 讀取未提交active瞬間值
  • UI直讀產物檔或使用file URL繞過驗證
  • adapters解析/批准業務approval
  • 將測試通過外推build/功能驗收
  • 模板任意eval/shell/網路/Plugin

contracts
  • write_new只能create_new，不覆寫stage內同名檔；以ASCII casefold檢查碰撞，拒reparse/hardlink和穿越。

reader_consistency

hazard
FileCommit可能先發布active再驗證/回復；直接read(active.json)會看見尚未完成的瞬間值，因此不允許consumer繞過讀租約。
rule
GenerationReadLease在同一active側檔取得OS共享read handle；與FileCommit exclusive writer互斥，允許多reader。側檔必須已存在，reader不create、不寫。取得後唯讀檢查IO journal：PREPARED/未知/損毀/RecoveryRequired拒絕，合法terminal需與active bytes一致。缺協調檔/未Ready namespace拒絕，不假稱已初始化。
lifetime
HOST持read lease到active/manifest解析、所有檔hash與完整性驗證及byte snapshot複製完成才釋放。M03接收此不可變byte snapshot，不再直接讀活動檔案。writer不得在持read lease時重入；同一用例鎖順序為namespace bootstrap（若必要，先完成並釋放）→active writer或reader二選一→stage handle。
readonly
初始化已完成的唯讀專案可用read-only handle讀；寫權不足不自動降級為未協調讀取。生成不可用不妨礙另一模組以原既有流程檢視.ess。
scope
新增的是本提案的consumer能力與private coordination seam，須確認後才建骨架；不把IO-A-F1原生證據當已完成。

publication_flow

  • step
    prepare
    effect
    只讀定義、可信catalog/SPEC。HOST用既有SpecStore驗證所需revision為Approved、content_hash與來源相符，再映射WORK policy；不足SaveOnly或明確error。讀現行active必持read lease；捕捉base digest。渲染bytes與plan只存在HOST本專案session。
  • step
    confirm
    effect
    請求只有plan_id與預覽digest，不接受UI回傳路徑/任意files。檢查同project/session、完整typed定義相等與revision、template raw hash和approval來源仍有效。initialize之後取active writer lease；再次比對base digest。
  • step
    prepare-owned
    effect
    分配generation_id、exclusive stage，逐個create_new寫入已預覽bytes，sync/驗證每檔、manifest及tree；全部通過才seal到versions，不自動接管任何既有目錄。
  • step
    activate
    effect
    仍持writer lease，再檢查definition/template/approval綁定未變；replace_checked(base_digest,active bytes)。receipt成功後回GenerationActivated；COMMITTED後cleanup問題沿IO語意，不把已提交誤報為未寫入。
  • step
    reader
    effect
    取得共享read lease＋檢查IO journal；讀active，核對project/序號/id；解析manifest raw bytes＋digest及投影；verify_sealed得到有界byte snapshot，釋放lease後交給consumer。Busy保留前一已驗證snapshot並標示尚未刷新。
