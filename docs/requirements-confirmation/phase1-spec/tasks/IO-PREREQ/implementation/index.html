4. Ports、Adapters、狀態與交易邊界

邊界規則
Input Portcreate_directory_exclusive / acquire_write；lease.read_current / replace_checked
Output / driven現有 Windows filesystem/native handle 與 SPEC SHA256；無新依賴
Authoritative state正式文件仍為正式資料；journal 只表示該次交易，非 M07 快照或專案 SSOT
Ownershiplease 擁有 OS handle；單次交易只追蹤 exclusive-create 取得的暫存
Mutation持鎖 replace 修改單一目標；acquire 只讀辨識，不恢復或清理
TransactionAcquire → Validate → PrepareOld/New → PREPARED → Recheck → Publish → Verify → COMMITTED → Receipt；失敗 Restore → Verify → ROLLED_BACK，無法確認則 RecoveryRequired

5. 契約與不變量

階段成功／失敗規則
exclusive create / acquire名稱非法 InvalidPath；存在 AlreadyExists；live OS handle Busy；無 journal 正常路徑可供後續取得；未完成/未知/損毀 journal 或有無法歸屬的 area 內容為 RecoveryRequired；不改正式檔、不清理 sidecar 或未知 area
prepare 或 PREPARED 發布前故障原 bytes/不存在維持且可證明只留下自有可診斷物時回 Storage；不確定完整性/所有權則 RecoveryRequired；不刪他人 collision；原不存在不建立正式檔；無 journal 但留有 scratch 的 area 下次 acquire fail closed
PREPARED 已有效後、publish 前偵測外部變更Conflict，保留外部版本；本次 owned 準備資料與可診斷紀錄可保留，下一次遇未終結紀錄仍 fail closed；不以 old 覆寫外部新版本
publish / verify / COMMITTED 寫入失敗先回復 old 或原不存在，再驗證，並寫入且重讀驗證 ROLLED_BACK 後回原失敗 stage 的 Storage；回復/驗證/終態記錄失敗則 RecoveryRequired；刪除新目標前須確認仍是本次 new，外部已改則拒絕刪除並 RecoveryRequired
COMMITTED 已寫且正式 new digest 驗證成功回 receipt；後續 cleanup 失敗不反轉為普通 Storage 或假稱沒提交；保留有效終態與未清資料；不在此階段回滾已成功交易
cleanup只按已驗證 terminal record/hash 清理 owned old/new；保留 journal 到 artifacts 清理完，journal 最後移除；下一次 acquire 對殘存 terminal record 只讀核對，不清理；只刪檔不遞迴；未知 entries/不相符 hash 一律不刪；只能後續 replace 的持鎖 prepare 階段完成可證實安全的 terminal 殘留清理，再開新交易
crash 與 reopenPREPARED/RECOVERY_REQUIRED/不完整 next/壞 journal 都 RecoveryRequired；有效 COMMITTED+target=new 或 ROLLED_BACK+target=old/absent 可取得 lease（僅診斷，不自動清理）；不符則 RecoveryRequired；所有不確定檔案保留；terminal 清理可能缺少 old/new，允許只在終態與正式檔吻合時忽略已刪除 artifact；仍存在 artifact hash 不符則拒絕

6. 禁止依賴與保護範圍

不改公開 Port/API、schema、ownership、交易語意、Undo、M07 清理政策。沒有 Domain→FS、UI→adapter、隱藏全域鎖、遞迴刪除或按鎖檔年齡刪鎖。原生 unsafe 僅在私有 handle identity FFI 包裝內，crate 其他 unsafe 禁制不變。

  @IO-BDD-02
  規則: 已有目標不變
    場景: 已有目標不變
      假如 目標為檔案、空目錄或非空目錄
      當 要求建立
      那麼 AlreadyExists；既有bytes及內容不變

  @IO-BDD-03
  規則: 非法名稱
    場景: 非法名稱
      假如 名稱空白、保留名、含separator或穿越
      當 建立目錄

  @IO-BDD-04
  規則: 同程序競爭
    場景: 同程序競爭

  @IO-BDD-05
  規則: 跨程序競爭
    場景: 跨程序競爭

  規則: 程序死亡釋放
    場景: 程序死亡釋放
      假如 子程序持有lease且無未完成journal
      當 終止子程序後再取lease

  @IO-BDD-07
  規則: 新檔提交
    場景: 新檔提交
      假如 期望不存在且無目標

  @IO-BDD-08

    場景: 既有檔提交
      假如 期望digest等於現行bytes
      當 replace_checked(Some(old),new)
      那麼 寫入完整new，保留old版本直到交易確認

  @IO-BDD-14

  @IO-BDD-15
  規則: 未知或損毀journal
    場景: 未知或損毀journal
      假如 journal版本未知、校驗不符或含越界路徑
      當 acquire
      那麼 RecoveryRequired，保留所有原資料，不解析成可執行動作

  @IO-BDD-16
  規則: lease關閉

  @IO-BDD-17

    場景: 目標被外部改動

      那麼 Conflict且不覆寫；不聲稱防止任意非合作writer最後瞬間競爭

  @IO-BDD-18

    場景: 失敗不刪他人檔案
