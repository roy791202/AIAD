1 意圖與架構

建立單一application document owner，保全raw輸入與候選安裝，分離Editor內容修改與Viewer mock capability。這是新架構提案，未假稱現有DispatchHost已擁有session。

UI main/editor/viewer driving adapters -> strict role Tauri input ports -> DispatchHost application DesignOwner -> existing WORK DocumentSession + HOST C1 codec -> projections

DesignOwner depends on S1 pure APIs and C1 public boundary; Viewer mock state depends only immutable snapshot. No new domain infrastructure/Port/file persistence. M04 persistence remains an explicit unavailable input dependency.

Exactly one S1 DocumentSession owns content/history/baselines per manifest document; application binding and preview/candidate records are derived. UI owns only ephemeral render/mock local mirrors.

prepare raw candidate -> guarded validation -> revision/generation recheck -> one S1 commit -> projection notification; failed render does not undo content, failed candidate never installs

No change to DocumentSession API or constructors outside new owner initializer. Domain has no Tauri/serde/filesystem dependency.

semantic_profile Canonical payload is C1 validated compact JSON with all object keys recursively sorted by UTF8 bytes, array order retained, supported number values C1-canonicalized; preserve loaded selection/updatedAt/product_pass=false compatibility values in payload but exclude /selection,/meta/updatedAt,/product_pass from semantic fingerprint projection. Hash fingerprint bytes sha256. These values are not edited by selection/time/view events. Any profile change requires replanning; raw file hash is separate M04 concern.

mutation All property/layout/create/delete/guide/grid/Form changes submit closed full-candidate design_json + expected revision. Validate structure, supported node types, unique stable IDs and all parent refs; no implicit remapping or label lookup. Use existing S1 prepare(Edit, validated_after) then commit once; no mutation if candidate semantic content identical (return current projection without commit). Clear uses existing Clear; undo uses existing S1 undo; redo deferred because no public S1 redo API. Never mutate UI then declare host success retroactively.

unsupported Read-only preserved projection, inert placeholders, unsupported ID/type list. No source-node filtering/stamping/Form insertion. Editing, save, and Viewer mock entry disabled while unsupported types/missing root Form exist. User must use a future explicit supported conversion workflow; no silent repair. Unknown scope labels remain data and grant no capabilities.

writer Exactly one current writer: main or ui-editor instance. Viewer never writer. Current writer explicitly grants to an existing trusted ui-editor/main window nonce using design_binding_transfer; transfer increments generation, revokes candidates/preview sessions, preserves S1 content/history/revision. Transfer to missing/remote/viewer denied. Window destruction retires writer; replacement writer requires authenticated main claim with explicit confirmation, not matching label alone.

projection All views receive raw validated canonical design_json plus revision/generation/dirty/can_edit/unsupported metadata. UI JSON.parse only after HOST C1 validation. A stale response cannot replace newer projection; rendering failure leaves old display with stale badge and authority remains HOST.

persistence No new H2 filesystem-save path. design_document_save returns DependencyNotReady(M04_S2) until an approved M04 persistence input seam is wired in a separately reviewed integration slice. Legacy uidesign_save_design/load_design/build_preview handlers fail closed with DESIGN_OWNER_REQUIRED for authoritative owner operations; no typed/raw root bypass. Existing exported communication preview remains explicitly non-authoritative; it is not upgraded to trusted Viewer IPC in this slice.

boundaries Session/runtime teardown loses unsaved state only after explicit discard confirmation; this H2 proposal adds no autosave/recovery store. M04/M07 integration readiness remains separate; owner emits completed mutation observations only, never claims snapshot persistence.

request_records All commands carrying request_id use runtime key(binding_ref,session_uuid,operation,request_id) with immutable typed capture. Validate caller first, then same-ID identical capture returns retained original terminal result with replayed=true and no extra commit/undo/save; different capture RequestConflict. Matching in-flight request Busy. Capture revision checked for new requests, never use a repeated request to mutate newer revision. New request_id with used candidate -> CandidateUsed. Retain until owner closed, at128 keys per binding/1024 runtime refuse before reservation, no eviction/time-based retry. No durable exactly-once across restart. Close/revoke removes replay authority; late response never installs over newer projection.

open_dependency design_binding_open must use an approved M04 owner-open input dependency to obtain identity-bound validated snapshot/baselines. Until that dependency exists return DependencyNotReady(M04_OWNER_INTEGRATION), no direct legacy load or invented initial content. Test doubles supply immutable approved-shaped snapshots in RED/component tests; they are not native integration proof.
