2. Architecture and Boundaries

hexagonal

Viewer driving adapter → exact Tauri intent input port → proposed DesignOwner application → immutable snapshot / C1 numeric guard output seams → detached mock state

dependency

UI → Tauri → DispatchHost → application owner → existing pure domain; no generic dispatch or concrete IO

ownership

Existing S1 owner retains document content/history/baselines. Proposed preview record owns detached mock/sequence only. Native actual instance resolves preview consumer and captured owner/document/generation/revision. No client authority fields.

transaction

Validate → resolve trusted native preview/owner → revision and sequence → immutable capabilities → optional exact C1 guard → actual delivery recheck → checked sequence + detached commit atomically. Overflow closes preview without mock update.

Forbidden effects

  • content write
  • history write
  • save
  • FileCommit
  • ACK
  • network
  • filesystem
  • eval
  • invoke by action string

3. Module Contract and Invariants

  • Only exact action/payload variant accepted
  • No failure consumes sequence; overflow only closes preview
  • Old accepted sequence gives SequenceConflict, no second effect and replayed=false
  • Actual consumer/owner/document/generation/revision checked at admission and delivery
  • No synthetic revision+1; unbounded/equal/missing changed observation fails DependencyNotReady
  • C1 number canonical result is trusted provider fixture, no float proof
  • All decisions including exact roots/error precedence and named seams PROPOSED_PENDING_OWNER

Trusted premises, not proof

  • Native/provider fixture objects are server-controlled premise inputs, never request fields
  • Instance/generation observations, provider reachability/authenticity/atomic lock not implemented or proved
  • nodes already immutable validated unique stable-ID projection; item schema validity is provider premise
  • C1 accepted canonical output already exact representability validated; model does not prove C1
  • Lower distinct revision is bounded schema witness, not monotonic native reachability claim

4. Viewer UI Schema

component: Viewer mock controls

role: Viewer

controls: Button Activate; CheckBox SetToggle; TextBox SetText; NumberInput SetNumber; ComboBox SelectItem

validation: typed exact payload; UTF8 text<=4096, node<=256, number token<=128; declared immutable stable item ID only

defaults: begin projection, not guessed content

disabled: stale/closed/unsupported/unresolved capability

success: inert detached delta only, no formal success/save toast

error: retained mock except overflow closed; focusable inert text aria-live

empty: missing node rejects; no fabricated node

accessibility: keyboard controls and inert text rendering pending native verification
