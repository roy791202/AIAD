architecture_proposal
hexagonal_view
UI/timer adapter -> authorized HOST recovery use case -> WORK recovery eligibility/state policy. HOST -> stable capture capability + recovery publisher capability + monotonic clock abstraction <- owning document/material/native adapters.
dependency_view
M04 committed immutable content + M05 pinned material versions -> M07 captured envelope -> recovery store payload -> single published index acknowledgement -> WORK baseline. Formal saver updates only its separate baseline.
ownership
Document owner owns current content and mutation barrier; M05 owns immutable material identity; M07 owns recovery baseline and attempt state per session. Captured envelopes and history items are projections, never document SSOT.
mutation_boundary
No UI/timer direct filesystem writes. Capture owner provides stable immutable semantic content. Recovery completion may advance only matching session attempt; it cannot overwrite the active document.
transaction_boundary
Acquire stable content + necessary asset claims -> release short capture barrier -> persist immutable payload/materials off UI -> publish durable index -> acknowledge captured fingerprint -> convert temporary material claims to retained snapshot roots. Failure before index acknowledgement never advances baseline.
reader_boundary
Enumerate and open only validated payload/index consistency. Uncertain/unsupported/incomplete entries remain visible with reason where safe, never automatically treated as successful capture.
proposed_states
  • Idle
  • DeferredMutation
  • Capturing
  • Writing(attempt)
  • WarningPendingRetry
  • Closed
attempt_binding
  • project_id
  • session_id
  • attempt_id
  • captured_revision
  • captured_content_fingerprint
  • asset_manifest_digest
success_transition
Writing(A) + durable index acknowledgement for A -> recovery baseline = A.captured_content_fingerprint; current fingerprint is reread independently. Never baseline=current merely because write finished.
failure_transition
Writing(A) + failure -> unchanged successful baseline; retain changed state and materials needed for recovery; next scheduled check retries after no operation overlaps.
close_transition
Closed session never accepts a completion into another session. Any already-published version retains original session identity; no destruction merely because editor closed.
pure_slice_candidate
Policy(state, monotonic check event, stable current fingerprint, mutation/inflight flags) -> Skip / Defer / RequestCapture. Completion(state, matching attempt outcome) -> new policy state. No FS, OS timer, hashing implementation or ownership migration in this slice.
non_goals
  • No adoption of M02 generation store protocol for recovery without its own review
  • No automatic retention limits or GC
  • No change to core DirtySet or existing selection Undo
  • No UI authority migration or blanket editing of app.js
proposed_defaults_not_confirmed
  • Use monotonic elapsed time for checks; resume performs at most one catch-up check. No timer backlog writes.
  • A deferred check is eligible once stable state is available, but no concurrent attempt; event/timer integration must be frozen in exact design.
  • Compare semantic content fingerprints, not only increasing revisions; content restored to previous snapshot is equal. Canonical field list and hash profile remain pending.
  • Retain unprocessed snapshots and candidate artifacts conservatively; physical cleanup has separate approval and complete-root prerequisites.
