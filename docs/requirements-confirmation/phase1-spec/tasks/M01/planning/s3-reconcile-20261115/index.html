3. FAIL-2：binding_status 枚舉對齊

獲勝閉合集合＝dto-contract.json responses.Save.binding_status：unchanged|bound|detached|committed_unbound。不新增 eligible。

  • unchanged：不切換 current project（含預先提交失敗、Partial、RecoveryRequired）
  • bound：伺服器完成授權 settings bind；唯一表示 UI 已切換 current project
  • detached：owner 已非 current；S2 證據保留；不切換、不 rollback
  • committed_unbound：S2 已提交；settings bind 失敗；保留 proof；不得改寫成 unchanged failure

RQ10 合併 FAIL-1+FAIL-2 後的完整建議字句（一次替換）：

Transport fields are the closed Save response in dto-contract.json: request_id UUID, operation save|finalize|adopt, captured_revision u64 decimal string, replayed boolean, outcome, binding_status, nullable projection. outcome wraps the exact adopted S2 result without discarding evidence. binding_status is the closed enum unchanged|bound|detached|committed_unbound and is the same field as dto-contract.json responses.Save.binding_status. Do not emit eligible. unchanged: no current-project switch, including pre-commit failure, Partial, and RecoveryRequired. bound: server completed the authorized settings bind for this captured owner, request, draft and revision; this is the only value that reports a UI current-project switch. detached: owner no longer current; S2 evidence retained; no current-project switch and no rollback. committed_unbound: S2 committed; settings bind failed; proof retained; do not rewrite as unchanged failure. Exact DTO and error mapping is dto-contract.json in this packet (requests, responses, errors, s2_mapping). It is not remaining S3-G5 work. S3-G5 leftover after this sentence is only Owner adoption of that closed mapping plus the already-specified permissions/UI-migration text; not a second mapping exercise. This sentence does not grant Owner adoption, Skeleton, native PASS, or RED PASS.
