M01-S3 Native selection／Owner 生命週期提案

待採納子提案；不是完整 S3 精確包，不是 Skeleton 授權。

本輪發現

目前已有 main/local origin 授權 guard 及 HostState → AppState lock-order 先例；WORK registry 既有 ownership 不應重建。S2 的非空 authority 字串明確不等於 native 授權。

兩個架構視圖

UI -> authenticated native command -> DispatchHost wizard owner -> S1/S2 use cases -> existing IO ports

Native picker -> trusted observation -> owner-bound selection -> immutable request -> S2 persistence -> authorized UI projection

WORK owns registered projects/leases; HOST application owns runtime wizard and request records; domain owns definition; IO owns private journal.

Owner reservation is runtime-only; adopted S2/IO commit unchanged; presentation authorization follows retained persistence evidence.

精確建議

OW1 Actual caller
Use injected WebviewWindow label and URL, never JSON caller fields. Propose reusing existing guard_owner_caller_allowed policy: main only, no explicit port, tauri://localhost or http(s)://tauri.localhost. Existing command allowlist and capability permission are additional gates, not substitutes. Development localhost:1420 remains denied unless separately approved.

OW2 One owner generation
Propose one active wizard owner per main-window instance, identified by server-issued runtime epoch and monotonically changing owner generation. DispatchHost owns wizard records separately from WORK project registry; WORK continues owning registered projects/leases. Opening wizard does not register a project, change HostSettings or acquire a Run lease.

OW3 Native selection
Only an authenticated native picker result can mint an opaque selection ID. Record binds canonical parent/root, selection purpose, window instance and owner generation. UI sees ID and display path; display path is never accepted as write authority. Cancellation mints nothing; rejection leaves existing selection unchanged.

OW4 Picker race
Capture owner generation before opening native dialog without holding HostState/AppState locks. On return revalidate actual window instance and generation before installing selection. If owner changed, discard selection with STALE_OWNER; do not overwrite new owner state or start persistence.

OW5 Capability lifetime
Selections are reusable only by their live owner generation and allowed purpose. Reselect invalidates prior unreserved selections. Already reserved request keeps its immutable captured selection for completion; invalidation detaches presentation rather than modifying a submitted request. Cross-window, expired generation and wrong purpose reject before IO.

OW6 Draft lifetime
Unsaved draft is runtime state only. Cancel/close revokes owner and drops unsaved draft after in-flight captures are detached; no implicit disk save or recursive cleanup. Reopening a saved draft uses explicit native selection plus adopted S2 open, constructs a fresh owner generation and domain projection; no resurrection of prior selection/request authority.

OW7 Project switch
An actual bound-project change revokes current wizard generation. A picker merely displaying another location is not a project switch. A matching committed wizard result may request binding through the existing authorized project-binding flow; failure leaves persisted evidence and reports committed-but-unbound, never ordinary unchanged failure.

OW8 Host locks
Preserve existing HostState -> AppState lock order whenever both are needed. Never retain either lock through native dialog or IO. Copy immutable capture under locks, release for IO, reacquire in same order and revalidate generation before installing projection. Exact production seam and concurrency tests remain part of full S3 Skeleton review.

OW9 Root proof
Native path normalization is infrastructure proof, not WORK normalize_light/case_fold_key identity or a label comparison. Re-check selected root/parent availability and target confinement at save; exclusive create/CAS remains S2+IO authority. No precheck authorizes overwrite or aliases. Exact native canonicalization/reparse policy and failure-injection seam remain an explicit unresolved full-packet gate.

OW10 Existing authority bridge
Construct adopted DefinitionAuthorityContext only from live trusted selection/session/window record after validation. Nonempty strings and UUID syntax are not authorization. Do not modify S2 context shape or create a second project identity registry. Candidate new wizard state is application-owned, requires adoption, and cannot be inferred from standing implementation permission.
