兩個架構視圖與資料語意

UI / native input → trusted M04 input boundary
                                 ↓
                 HOST save orchestration → WORK DocumentSession
                       ↓              ↓ content/history/baselines owner
             codec abstraction + current FileCommitPort ← adapters

IO private journal/versions remain adapter-owned.
Capture R / semantic A → codec bytes / raw E
                         ↓
          expected old disk D → verified CommitReceipt(E)
                         ↓
               ACK captured R with semantic A
                         ↓
     live R+1 remains dirty; recovery baseline unchanged

raw E ≠ semantic A is valid; they must not be interchanged.

需先回規劃的精確缺口

M04-S2-R1 · REPLAN_REQUIRED_FOR_PROPOSED_PERSISTENCE_BOUNDARY

Historical storage proposal describes M04-level document-versions/document-transactions paths, whereas current accepted IO adapter owns private version/journal mechanics and success receipt does not expose an old-version handle.

缺少：Explicit current M04 consumer contract distinguishing IO private recovery artifacts from any separate user-facing retention requirement.

建議：Consume actual FileCommitPort without duplicating its private journal. Keep original retention path proposal historical, not a new write target. If long-term document version history is required, propose it separately with its own approved lifecycle/Port rather than silently implementing it.

M04-S2-R2 · ARCHITECTURE_INCOMPLETE_CODEC_AND_ERROR_TYPES

DocumentCodecPort proposal still names DocumentFormat/CodecError and full-document canonicalization/preservation responsibilities without fully frozen types, exact per-format field exclusions and complete codec fixture/error oracle mapping.

缺少：Precise ESS XML profile, .sgendesign dependency/adoption contract, semantic canonical payload versus raw persisted bytes, actual codec-owned error shape.

建議：Prepare one exact codec/type/error/field-map package. Reuse M03 only after its contract is adopted; do not treat scene text helper or packet read-only extraction as full serializer. Do not implement the absent codec adapter from placeholder names.

M04-S2-R3 · ARCHITECTURE_INCOMPLETE_SAVE_PROOF_AND_ACK

WORK acknowledge_formal_save expects semantic digest, while CommitReceipt.committed_digest hashes exact encoded file bytes. The two may legitimately differ; trusted HOST must bind both to the same immutable capture, target, request and owner.

缺少：Exact captured-save record, receipt-validation result and postcommit acknowledgement error/late-owner semantics.

建議：Propose immutable capture binding with document/session/project/request, captured revision+semantic digest, encoded bytes+raw digest, expected previous raw digest and trusted target. Validate target/raw hashes/previous digest/txid before ACK. ACK only semantic digest from captured content, never raw receipt digest. If disk commit succeeds but ACK cannot apply, preserve persistence proof and report committed/ack-deferred instead of ordinary failed-unchanged.

M04-S2-R4 · ARCHITECTURE_GAP_RECOVERY_BLOCKING_SEAM

Approved S1 has status RecoveryRequired and rejects edits while in that state, but no public transition method exists to enter it from a native IO outcome. Silent state reconstruction or a new setter would change the accepted Skeleton.

缺少：Approved location/owner of IO safety gate and how its state combines with DocumentSession status.

建議：Prefer A for current S2 integration if complete boundary coverage can be proved; present exact model and all-entry guards for one review before Skeleton. Do not self-approve either option.

A：Proposed per-session HOST IO-health guard owned by existing M04 application/session boundary; all destructive inputs check it before calling S1. Domain content/history status unchanged; projection explicitly combines IO health and domain editability. Requires precise guard lifecycle/DTO scope approval, no global manager.

B：Explicit new domain transition API and lifecycle contract to enter/resolve RecoveryRequired. Requires S1 public API/Skeleton/TDD revision and Owner adoption; cannot be treated as local implementation.

以上不是已批准契約互相矛盾的SPEC_CONFLICT：M04舊候選儲存機制本就待精確審查。此輪釐清與現行IO邊界的差額，不自行選定新架構。既有S1無IO gate的事實不等於重開或否定其已接受純領域範圍。
