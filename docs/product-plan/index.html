02 / 使用者、範圍與非目標

使用者與核心旅程

專案負責人：選專案 → 審閱架構 → 核准封包 → 啟動 Agent → 查看阻塞 → 驗收 → 發布核准。

開發者：查看 BDD/TDD、diff、Run log 與回歸證據。架構審查者：檢查 Ports、ownership、交易與越界。

價值指標：工項規格完整率、證據有效率、阻塞原因完整率、跨專案誤寫次數、可重現建置比例。數值為驗收要求，不是已測成效。

首版範圍

單機 Windows、多本機專案、單個同時執行的 Agent、Git CLI、看板、架構 DAG、工程封包、真實測試證據與 Windows 部署閉環。

後續／非目標

多使用者 RBAC、雲端 worker、多 Agent 並行、多機調度、任意外掛市場、SSH/容器/DCC 真實 Adapter 留待 M4。首版不承諾任意程式碼的完全語意判定或自動架構批准。

03 / 技術基線

層建議決策理由／限制
桌面Electron原生檔案選擇、IPC 與視窗；主程序只負責宿主與受限橋接
UIReact + TypeScriptTasks、規格詳情、部署面板；不直接讀寫 Git 或 shell
圖形React Flow + ELK.js圖形互動與排版；循環驗證由領域規則負責
流程XState（封裝）實作核准狀態機；持久化不代表外部命令 exactly-once
執行Node.js 獨立 worker + provider adapter長命令不阻塞 UI；取消、崩潰對帳與安全界線需另作設計
規格module.html 內 ModuleSpec JSON每模組一份人類表面與機器資料；渲染 DOM 是投影
執行資料SQLite + artifact filesrun/event 交易與證據索引；大型 log 不塞 DB；禁止複製規格權威
測試候選Vitest / Cucumber.js / Playwright單元與 Contract／Gherkin／UI；實際版本在工具 spike 與 lockfile 固定

此選型延續 Electron + React 建議；ComfyUI 的 Vue/Python 是參考，並未轉為本產品框架。第一版不必加入 HTTP 伺服器；UI 經 typed IPC 操作 use cases，將來遠端服務需另外核准。

04 / 系統邊界與模組 DAG

以下為 PROPOSED 架構，不是 ARCHITECTURE_APPROVED。依賴箭頭 A → B 表示 A 使用 B 的公開契約；外部 Adapter 實作方向見六角形視圖。

系統邊界：本機 SGenAxis
Driving Adapters：Electron / React UI、CLI（後續）、Tests
                      │ Input Ports
                      ▼
Application：Workspace / Workflow / Execution / Git / Release use cases
                      │
                      ▼
Domain：Task state、Envelope、Contracts、Evidence validity、DAG rules
                      │ 使用內部定義的 Output Ports
                      ▲ 實作
Driven Adapters：Git CLI、Agent CLI、Filesystem、SQLite、Installer
                      │
外部邊界：專案目錄、遠端 Git、Provider、OS 程序、部署目標

依賴向內：Adapter → Port；Application → Domain / Port。
Domain 禁止依賴 React、Electron、Node filesystem、SQLite、Git CLI 或具體 Provider。
所有 mutation 經 input port / use case；UI 與 HTML 不直接改權威資料。

所有權與失敗原子性

Spec 匯入：讀取 → 驗證完整模型 → 寫暫存檔 → 原子替換。Project 重新定位：探測身分 → 確认無租約 → 原子更換 binding。Run：保存 intent → 啟動外部程序 → 保存事件與結果；重啟以 operation ID 對帳。部署：step checkpoint + 明確補償；檔案、DB 與外部系統沒有虛構的跨系統 ACID 保證。

SQLite 中可存 spec hash / revision reference，不能保存可被獨立編輯的第二份規格。未提交的工作樹亦需指紋；只有 commit SHA 不足以表示實際測試內容。
