流程與核准 / 模組工程規畫

擁有 Task 執行階段、核准紀錄與前置條件

架構 PROPOSED；Contracts/BDD/TDD 為草稿；實作 NOT STARTED；回歸 NOT RUN；健康未評估。

架構位置、所有權與 Ports

系統邊界：本機 SGenAxis
Driving Adapters：Electron / React UI、CLI（後續）、Tests
                      │ Input Ports
                      ▼
Application：Workspace / Workflow / Execution / Git / Release use cases
                      │
                      ▼
Domain：Task state、Envelope、Contracts、Evidence validity、DAG rules
                      │ 使用內部定義的 Output Ports
                      ▲ 實作
Driven Adapters：Git CLI、Agent CLI、Filesystem、SQLite、Installer
                      │
外部邊界：專案目錄、遠端 Git、Provider、OS 程序、部署目標

依賴向內：Adapter → Port；Application → Domain / Port。
Domain 禁止依賴 React、Electron、Node filesystem、SQLite、Git CLI 或具體 Provider。
所有 mutation 經 input port / use case；UI 與 HTML 不直接改權威資料。

idFLOW
name流程與核准
responsibility擁有 Task 執行階段、核准紀錄與前置條件
layerDomain / Application
inputIWorkflowCommands

adapterSQLiteWorkflowStore, ExecutionAdapter
transaction狀態與事件同一交易提交；外部操作用 operation ID 對帳，不承諾 exactly-once

依賴目標：SPEC, WORK, GUARD, EXEC, EVID

完整模組 DAG 見 系統架構。此模組只允許經自身 Input Port 修改其權威資料。禁止跨模組直接資料庫寫入及 Domain 基礎設施依賴。

Agent 執行順序

  1. 確認 primary module、ADR 與封包核准版本
  2. 建立對應 skeleton/test seams；不得改已核准語意
  3. 依 fixtures 與 TDD 設計寫可建置測試
  4. 執行測試並證明是指定缺失行為造成 RED
  5. 只在 allowed_scope 實作
  6. 執行相同測試達 GREEN；禁止弱化 assertions
  7. 跑模組與相關回歸，分類每個失敗
  8. 審查 diff/Contract/BDD/架構與驗收，更新 module.html；待人核准 commit
