01 / 產品與交付狀態

SGenAxis 是本機優先的工程控制台：以四色燈號管理工項（灰待辦／黃進行中／紅阻塞／綠完成，綠燈可再由使用者「確認驗收」），依優先序把卡片派給多條 Agent 通道，依排程自動開工或收工，並統計每日／每週／每月的完成率。

這一版的邊界：規則與狀態機是真的（Core 全部實作並有測試）。工項與派工狀態已存成專案資料夾內的 JSON（<專案>/.sgenaxis/tasks.json，hb-board/1 格式，鎖檔＋原子寫入）；啟動時先顯示 Beta 看板的唯讀快照（80 張＋1 個版本，SHA-256 已核對）。Agent 預設由 DryRunLauncher 模擬；在「設定 › Agent 啟動」可對目前專案切到實際啟動（ProcessLauncher，只限 D:\AIAD\_sandbox 底下的專案，切換專案即回到模擬）。回報走與 Beta 相同的三條管道（回報檔、輸出標記、回報指令）加上畫面上的「模擬回報」。佈版頁的版本來自看板紀錄、成品與 dist/ 即時檢查；Git 頁只對 SGenAxis 建立且有自己 .git 的專案執行唯讀查詢。Git 寫入、Clone、部署、提交仍只在狀態列留下提示。

02 / 分層架構（Mode A：獨立桌面應用）

控制流由上往下；編譯期依賴一律指向內層。Core 定義 Port（Protocol），Adapter 實作 Port：Core 不依賴 Qt、不讀寫檔案、不讀系統時鐘、不啟動子行程，所以派工狀態機與排程可以用 ManualClock 和 DryRunLauncher 在毫秒內測完。

綠色虛線：MainWindow 直接呼叫 Session／Dispatcher 方法（唯一的狀態變更入口）。藍色虛線：Adapter 實作 Core 定義的 Port（依賴指向內層）。in_memory.py 雖然放在 core 套件裡，但它只是 Port 的純記憶體實作，供種子資料與測試使用，不碰作業系統。

06 / 關鍵資料流

A. 使用者改變工項狀態

狀態下拉→ status_changed(id, status) →session.set_item_status(actor="user")→board.set_status：寫 started／completed、加紀錄、version+1→store.commit(item, expected_version)→refresh()

選「已驗收」等於「綠燈＋確認」，只有使用者可以做；Agent 嘗試會被拒。TASK-Y1 仍被 Session 擋下（「可重現工具鏈與測試骨架不進入已驗收頁」）。版本不符時拋 VersionConflict（「這筆剛被別人改過，已重新載入。」）。

B. 派工一張卡

通道「開始」或排程觸發→dispatcher.start_lane→select_next：紅 > 黃 > 灰，再依最舊更新時間；略過綠燈、note／epic／milestone／release、別的通道手上的卡、needs-human 卡→灰 → 黃（Agent 寫入）→launcher.launch(LaunchRequest)

LaunchRequest 只帶 Agent 規格展開後的參數（不含卡片文字；argv[0] 之後每個參數都要符合安全字元，含權限繞過旗標的規格直接拒絕），提示詞寫到 .sgenaxis/logs/<runId>/prompt.md，環境變數帶 HB_BOARD_TASKS、HB_DISPATCH_RUN_ID、HB_DISPATCH_CARD、HB_DISPATCH_REPORT_FILE、PYTHONIOENCODING=utf-8。提示詞有「看板 JSON（必須更新）」一節，告訴每個 Agent 看板檔的位置，並要求以回報更新它、不要直接手改；同時有其他通道在跑時，會列出它們手上的卡。

C. 回報與結束

回報檔 report-inbox/<runId>.json・輸出最後的 HB-REPORT: 標記・回報指令・模擬回報→tick 每秒檢查；第一個有效回報算數，之後的記為「已忽略」→完成 → 綠；阻塞 → 紅＋註記並放入略過清單→還有額度就派下一張；否則閒置

回報指令：python "<SGenAxis>\sgenaxis_report.py" --card … --run … --file … --outcome done|blocked --note "…"（也可 python -m sgenaxis report；卡號、run、回報檔可由 HB_DISPATCH_* 環境變數帶入）。它只用標準函式庫與 Core，不載入 PySide6，所以 Agent 用任何 Python 3.10+ 都能執行；它寫入同一個回報檔並標記 "via": "cli"，已有回報檔時拒絕（exit 1），由執行中的工作台在下一次 tick（或重開時）套用並記為「回報指令」。結束碼：0 已寫入、1 拒絕或 I/O 錯誤、2 參數錯誤。

同一次檢查同時有回報檔與標記時，以回報檔為準。無效的回報檔留在收件匣並顯示原因；若這輪最後以別的方式結束，檔案移到 reports/rejected 並寫進 needs-human 註記。程式結束後還會再等 20 秒讓晚到的回報檔進來。沒回報、逾時、被中止、程式關閉、上次中斷（orphaned）→ 寫入 needs-human 註記與略過清單，不自動重試。沒有回報且輸出含額度用完／未登入字樣 → 卡片退回原燈號、通道進入錯誤並顯示登入提示；啟動失敗同樣處理。連續 3 次在 60 秒內結束且沒回報 → 通道錯誤（快速失敗）。

視窗模式（Antigravity）：啟動程式結束不代表完成，也不檢查額度／登入字樣與快速失敗；只有回報或逾時會結束這輪。逾時與立即終止都不會關掉視窗，註記會說明視窗需自行檢查；關閉程式時這輪保持原狀，重開後繼續等它的回報檔。

C2. 存檔與重新啟動

任何改變通道、執行、排程的動作→dispatch.json（鎖檔＋原子寫入，內容沒變就不寫）→重開：先套用關閉期間寫入的回報檔→視窗模式繼續追蹤；其他未結束的執行標成 orphaned、該通道進入錯誤

開啟既有專案不寫任何檔案（第一次存檔才建立 .sgenaxis/）；新增專案會建立資料夾與空的 tasks.json。有通道在跑時不能切換專案（「Agent 派工中，請先全部停止再切換專案」）。關閉主視窗會呼叫 shutdown()：非視窗模式的執行以 server-shutdown 標成 needs-human。

D. 排程

dispatch_timer 每秒→dispatcher.tick()→events_between(上次, 現在]→開始通道（記錄由哪個排程啟動）／時段結束只停自己啟動的通道

不補跑：第一次 tick 只記時間；兩次 tick 間隔超過 10 秒或時鐘倒退時，期間的事件全部略過。暫停全部排程時記錄「skipped-paused」。單次排程觸發後自動停用。

E. 外部動作（刻意不執行）

Pull／Push／Fetch… · Clone · 提交 · 開始部署→notice／_note→狀態列提示

Agent 提示詞明文要求「不得執行任何 git 指令」「不得呼叫任何 Agent CLI」；check_agent_spec 拒絕危險旗標（例如略過權限確認）與未知佔位符，resolve_argv 拒絕含不安全字元的參數。
