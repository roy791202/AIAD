# UX 原則：參考現有產品，避免過度設計

- 設計任何畫面前，先找 2–3 個市面同類成熟產品當參考，列出產品名稱、參考的畫面或流程、沿用的慣例。
- 優先沿用使用者熟悉的版面、元件與操作模式，不自創互動。
- 只做需求清單裡有的功能和狀態；沒有需求支撐的畫面、動畫、設定項一律不做。
- 偏離參考慣例要寫理由（對應哪條需求），寫不出就照慣例。
- 每個畫面都要有：空、載入、錯誤、降級狀態；停用的控制項要能看出原因。
- 產出：參考產品對照表 → 主要畫面 → 操作流程 → 各狀態（HTML 原型或 Figma）；最後逐一檢查有沒有超出需求的設計，有就刪。
- 專案已有的設計規範（色票、元件）見 [project.md](project.md)。
