# 上線就緒：測試、資料、可觀測性、安全、記憶體

一律以需求為準，不過度設計：單機桌面 App 不必硬上分散式交易、APM 或 JWT。預製期寫進非功能需求、架構、TDD 與工單；實作期寫在對的層；驗收期逐項檢查。

## 一、測試策略
- **單元**：領域層與 Use Case，用假 Port 隔離。核心業務覆蓋率 ≥ 80%，領域層目標接近 100%。
- **整合**：每個 Adapter 對真實依賴（資料庫、檔案系統、外部 CLI）至少一組，在各目標平台跑。
- **E2E**：從渲染層操作到資料落地的主要流程，對應 BDD，是介面實測的基礎。
- TDD 節奏與誰寫測試見 [bdd-tdd.md](bdd-tdd.md)。

## 二、資料一致性與併發
- 交易在應用層開（經 Port，例如 Unit of Work）；一個 Use Case 的多個寫入全成或全敗；領域層不知道交易。
- 讀多寫少用樂觀鎖（版本號），高衝突用悲觀鎖；桌面 App 也要考慮多視窗、多執行緒、背景任務同時寫入，寫明用哪種。
- 只有真的跨多個資料庫／服務才用 Saga（含補償）；避免 2PC。
- 寫檔用暫存檔＋原子替換；重試的操作要冪等。

## 三、可觀測性
- 結構化日誌（例：Rust `tracing`），分 INFO／WARN／ERROR；不用 `println!`／`console.log`。日誌是輸出 Port，領域層不直接寫。
- 每個請求／使用者操作在 API 層產生 Trace ID，貫穿各層日誌。
- API 層統一攔截未處理錯誤，記日誌後回友善訊息；絕不外露資料庫錯誤、內部路徑、stack trace。
- 有服務端時監控 CPU、記憶體、回應時間、錯誤率並告警；桌面 App 至少有本機日誌、崩潰報告、健康檢查。

## 四、安全防禦（分層）
| 層 | 主要漏洞 | 必要寫法 |
|---|---|---|
| API | SQL／指令注入、XSS、BFLA | 參數化查詢，絕不拼接 SQL 或 shell；輸出編碼與 HTML 消毒；每個端點／IPC command 宣告所需權限，攔截器統一檢查、預設拒絕；驗證格式、範圍、路徑穿越 |
| 應用 | BOLA／IDOR | 不信任客戶端傳來的 ID；身分從 session 取得，查詢帶擁有者條件或取回後驗擁有權 |
| 應用＋領域 | 商業邏輯漏洞（負數、溢位、非法狀態轉換） | 值物件建構時拒絕不合理值；衛句阻斷；金額用整數／decimal 並檢查溢位 |
| 領域／基礎設施 | 敏感資料外洩 | 密碼加鹽單向雜湊（見下）；敏感欄位遮罩；金鑰與 token 存 OS 安全儲存（經 Port），不進程式、設定檔或日誌；對外只回「系統發生錯誤 (Error Code: XXXX)」 |
| 基礎設施／CI | 已知漏洞套件 | CI 做 SCA（`cargo audit`／`cargo deny`、`npm audit`、Dependabot），高風險 CVE 就擋；鎖版本；新套件寫引入理由 |

- 有帳號時用標準方案（OAuth2／OIDC／JWT）＋ RBAC，不自創；Tauri 用 capabilities 只開放必要 command 與路徑。
- **密碼雜湊**：預設 Argon2id 或 BCrypt。例外：零相依的內部工具（例如看板伺服器，PowerShell/.NET 無內建 Argon2）可用 PBKDF2-SHA256（隨機鹽，迭代次數依 OWASP 現行建議），並在文件寫明例外理由。
- **TDD 必含安全案例**：SQL／指令注入字串、XSS 字串、越權呼叫、改 ID 存取他人資料、負數／零／極大值／溢位、錯誤回應不含內部細節。

## 五、記憶體與資源
| 原則 | 寫法 |
|---|---|
| 所有權與生命週期明確 | 優先借用 `&T`；跨執行緒用不可變資料或 `Arc<T>`，需寫入才 `Mutex`／`RwLock`；避免 `Rc`/`Arc` 循環（必要時 `Weak`）；TS 移除監聽、清 timer 與 subscription |
| 用到再配、用完即放 | 大物件在需要的分支內建立；檔案、連線、行程靠 RAII／`Drop`／`try/finally` 釋放 |
| 池化 | 連線、執行緒、HTTP client 用池或共用實例——**只在量測證明有成本時** |
| 防禦性上限 | 外部決定大小的配置（分頁、上傳、檔案、佇列、快取、訊息）都設硬上限；channel／佇列用有界版本；大資料用串流或游標 |
| 空間局部性 | 熱路徑用連續記憶體——**只在量測過的熱路徑** |

記憶體 TDD：超過上限的輸入被截斷或拒絕；大資料情境證明是串流（記憶體不隨資料量線性成長）；長時間執行的流程做一次記憶體穩定性檢查。

## 各層對照
| 層 | 負責 |
|---|---|
| 渲染 | 防 XSS、輸入提示、友善錯誤畫面 |
| API | 認證授權、輸入驗證、全域例外、Trace ID、結構化日誌 |
| 應用 | 交易、鎖、Saga（必要時）、冪等重試 |
| 領域 | 純規則、充血模型、接近 100% 單元測試 |
| Adapter | 參數化查詢、安全儲存、日誌遮罩、整合測試 |
| 跨層 | 效能預算與回歸（[performance.md](performance.md)） |

## 審查時
覆蓋率門檻、整合與 E2E、交易邊界、鎖、日誌遮罩、錯誤外洩、輸入驗證與權限、上表安全項、SCA 結果、記憶體（無上限配置、一次讀入大資料、資源未釋放、循環參照、無界佇列、無依據的池化）。驗證者跑覆蓋率報告與安全、錯誤情境。明顯違反就退回。
