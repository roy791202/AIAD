authority

Server resolves authenticated principal and run-bound reporting grant. Caller actor/accepted flags are untrusted. Reporting grant cannot create architecture approval, renew lease or accept task. Grant issuer, credential mechanism and revocation remain owner decisions.

ordering

Strict per-attempt sequence starting 1; gap rejected with expected sequence. Matching report_id+canonical payload returns original receipt; same report_id different payload is conflict. Identity/auth validation precedes receipt lookup. Old attempts/expired leases rejected. CAS revision conflict requires read/reconcile, not blind retry.

transaction

Validate shape -> authenticate -> verify binding/lease/cancellation -> duplicate check -> sequence and expected revision -> validate evidence metadata -> atomic append+receipt+run revision+derived projection. Failure before commit changes nothing; lost ack recovered by exact retry. Existing store atomic capability must be verified before implementation. No second mutable board.

evidence

Store opaque references and declared hashes/provenance. Ingestion is not verification. Do not execute referenced commands, fetch arbitrary URLs or trust claimed PASS. Progress/output/evidence/terminal execution are separate report kinds; evidence review and owner acceptance stay existing gated paths.

cancellation

Cancellation and report commit serialized on authoritative run revision. Cancelled/new reports rejected; an already committed duplicate may return receipt only under still valid reporting authorization. Reconnect does not resurrect run, lease or acceptance.

limits

Explicit proposed byte and evidence-count limits in fixture; truncation never silent. Output chunk ordering uses sequence; declared encoding. Transport adapters normalize errors but never mutate task stores directly.
