recommendation

First validate a benign local noninteractive fixture through the existing HOST/EXEC seam. allowed_and_forbidden_PROPOSED

allowed
An explicit local benign executable using argv tokens and an explicit disposable bound cwd; controlled modes such as emit-output / nonzero-exit / await-cancel are fixture requirements, not existing provider commands. Existing start_run/poll_chunks/cancel_run and settings path/args are reused only within owner-selected scope. After separate approval, one exact provider executable/argv may be tested.
forbidden
  • No Agent launch, login, token read/write, provider version invocation or authentication change in this planning task.
  • No shell command string, cmd /c, PowerShell -Command, shell expansion, eval, arbitrary request-supplied executable or dynamically appended unreviewed args in the proposed first envelope.
  • No broad auto-approve/permission-bypass flags, unknown network endpoint probing, automatic package install/update, persistent daemon/session, stdin dialogue or PTY fallback.
  • No task/report metadata accepted as authorization; no child output promoted into SPEC/GUARD authority or product acceptance.
  • No schema/Port/DTO/Manager/framework/dependency changes to fit a guessed provider interface.
scope_honesty
The existing ProcessPort is a low-level launcher, not a security allowlist or sandbox. These are proposed envelope restrictions that need a selected enforcement/fixture boundary; do not advertise that current executable/argv settings prevent arbitrary child actions.

input_output_contract_PROPOSED

input
Explicit selected executable + exact ordered argv vector + HOST-bound project_root/work_item_id/current fingerprint. Empty/invalid/unapproved path rejects under existing gates. No implicit PATH executable discovery or new secret-bearing args proposed; exact path policy to be approved for real installation.
source
If a module packet is supplied, bind its explicit source-relative path, exact .ess SHA256, moduleId/taskId, packet payload SHA256 and current project/worktree snapshot. Recheck freshness before handoff; no external UI discovery or XML repair. A NOT_READY packet can be inspected but cannot authorize implementation.
delivery_choice
For first fixture, use an explicit already-supported argv token naming a disposable read-only input file or literal fixture string. No new child stdin or request prompt field. For actual provider, whether input is argv/file/stdin and size/quoting/encoding limits are UNKNOWN until exact installed interface and user target are provided; unsupported required stdin => ARCHITECTURE_GAP, not silent port extension.
output
Capture stdout/stderr as existing text chunks with per-stream ordering; preserve existing lossy-UTF8 contract. First fixture emits fixed marker + known payload for exact assertions. Actual provider structured-output schema and permission/auth notifications are UNKNOWN; malformed/empty output is not accepted report evidence merely because exit0.
exit
Reuse existing exit classification and terminal-once after captured chunks. 0 means provider process success only, nonzero failure, cancellation as existing direct-child intent. No product green/acceptance. Plain wait-only error recovery remains existing follow-up, not fixed by this envelope.
cancel
Existing request-ack + continuing poll/drain, direct-child-only cancellation. Fixed2,000ms is an observed-post-exit drain check, not whole task runtime timeout. Both EOF at an observation can complete even if caller waited longer; otherwise open streams at elapsed>=2,000ms fail incomplete. Unbounded buffers and inherited-reader lifetime remain explicit limitations.
runtime_timeout
UNKNOWN for real provider and not added by this plan. Fixture harness may use a bounded test deadline solely to classify environment/harness failure; it must not be reported as production cancellation/timeout proof.
reports
HOST associates captured process observations with its accepted run/task/project/fingerprint and selected source packet hashes. Child-returned runId/taskId/PASS are untrusted claimed data. Report files may be reviewed as artifacts, but authenticated ReportRun/claim/lease/report_id/sequence/CAS semantics stay in the separately unapproved ingress proposal; no new acceptance grant is invented.
failure
Invalid/missing config, stale source or unapproved scope rejects before launch where enforcement exists; missing producer/input/report schema is NOT_READY. No automatic retry or interactive/login fallback. Auth-needed provider behavior must be detected according to verified installed interface; no guessed error-string classifier.

architecture

domain_application
Existing run/WORK lease and acceptance rules; HOST orchestrates accepted starts. No domain owns provider flags or authentication.
ports_adapters
Existing AgentPort and ProcessPort; CliAgentAdapter config mapping and StdProcess OS adapter. UI commands are driving adapters. No new protocol/session interface.
ownership_mutation
HOST/WORK own run/task/project/lease. EXEC owns output/terminal projection. Child is untrusted. First planning slice mutates none. Future fixture artifact/output files are isolated test data, not new SSOT.
transactions
Preserve existing preflight/start/lease and terminal reconciliation; source snapshot check is a handoff freshness check, not an OS write-isolation guarantee. New report commit transaction is excluded.
forbidden_dependencies
UI directly spawning provider; Domain depending on CLI SDK/FS; Agent writing board/SPEC directly; report ingestion bypassing HOST; interpreting process success as approval.
