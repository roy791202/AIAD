minimum_change_proposal

public_port
Add StreamCompletion { Open, Eof, Error(String) } and ProcessOutput.stdout_completion / stderr_completion. Default is Open; existing stdout/stderr/is_empty retain data-only semantics. Data and Error can coexist so already captured bytes are not discarded.
why_not_two_bools
EOF booleans alone cannot distinguish read failure from clean EOF. Existing reader silently ignores read errors; this must not become false complete output.
adapter
One private per-stream buffer/status record under one mutex; set Eof only on read Ok(0); retry Interrupted; other read errors become sticky Error. Mutex poison returns existing PortError instead of silently treating it as empty. No blocking joins.
application
Store observed exit code, optional post-exit Instant deadline and cancellation intent inside existing ActiveRun/Live fields. Poll nonblocking, drain data, observe exit and stream status, then decide terminal. No new public run state enum/API.
cost
+0 production files/dependencies/managers; +1 enum,+2 fields. Core edits5 existingfiles including ports/lib.rs one-line re-export. Integration A adds2 existingfiles=7total; previous4/6 estimate omitted enum re-export. No extra public API.
alternatives_rejected
  • Delay try_wait Some(code) until EOF: changes public exit semantics and can hang on inherited handles.
  • Join reader threads synchronously after child exit: violates nonblocking polling and can hang.
  • Two empty reads / arbitrary sleep: no evidence of EOF; timing workaround cannot guarantee final output.
  • New process manager/repository/scheduler: no behavior requires these abstractions.
pattern_ROI
Pattern: none. Trigger: missing explicit completion contract. New abstraction hierarchy: rejected. Existing ProcessPort already has real/fake implementations; extend only the observation required by module tests.

policies_CORE_OWNER_APPROVED

drain_deadline
2,000 ms monotonic time from FIRST observed direct-child exit (including successful cancel). Never reset on later chunks. Deadline enforced on next poll; no claim of unattended timer execution. This is a proposed finite engineering bound, not a measured reader percentile or existing guarantee.
boundary_order
At each poll first capture available data/state. If both streams Eof, complete even at exactly 2,000 ms; otherwise elapsed >= 2,000 ms means timeout. Running child has no new runtime timeout.
timeout_outcome
Keep already captured chunks; emit one existing AgentChunk::Failed with stable prefix PROCESS_OUTPUT_INCOMPLETE, exit code and which streams remained open. Never Exited Success/Cancelled for incomplete output. Local phase finishes; no later chunks. No retry.
reader_error
Retain captured chunks, emit one Failed PROCESS_OUTPUT_READ_FAILED naming stream (sanitized error, no program args). If direct child still running, attempt existing direct-child cancel once before terminal; cancellation failure included in same Failed. No false EOF/success.
cancel
Existing direct-child cancel remains idempotent. On success record cancellation intent, do not publish terminal until same drain rule settles. Both EOF => Exited Cancelled(-1); deadline/error => Failed incomplete/read-failed. Preserve naturally finished run if exit already observed before cancel. Existing swallowing of native kill/wait failures must be evaluated as RELATED_BLOCKER, not silently expanded in this slice.
buffer_and_descendants

## Required behavior and current skeleton

- `app.js:2125-2185 pollRunStream` breaks on an empty `chunks` batch (`:2145-2147`), then reports failure and clears activeRunId. Empty output does not mean child exit or EOF. This affects normal runs as well as cancellation.
- `src-tauri/src/dispatch.rs:675-682 cancel_run` calls EXEC cancel, performs exactly one poll, discards that poll's chunks, and returns only BoardView. A second delayed drain cannot happen through this operation. If chunks/terminal were produced, consuming them also prevents the UI from seeing them.
- `app.js:2287-2314 cmdCancelRun` increments polling generation before invoke, then calls finishRunUi and claims WORK lease released. With asynchronous drain, no terminal may yet exist; lease is released only by HOST `poll_chunks` terminal reconciliation (`dispatch.rs:626-649`).

- Architecture: existing CLI application-to-HOST/UI event-consumer boundary, no new architecture layer required.
- Business logic: cancel acknowledgment becomes a request accepted, not proof of completion; silence remains running/draining until an explicit terminal event.
- Contracts/invariants: INV-PROC-02,03,05,07; event preservation, terminal exactly once, truthful lease/busy projection.
- BDD: extend module cancellation/empty-output scenarios to HOST/UI integration; approval required before expectation changes.
- Skeleton: existing four-file core is insufficient. Minimum scope adds `src-tauri/src/dispatch.rs` and `ui/app.js` functions only, with integration tests.

- `take_utf8(buf: &Arc<Mutex<PipeCapture>>) -> (String, StreamCompletion)` drains bytes and snapshots state together. Implementation may return Result for poison handling using existing PortError; private helper shape is not public API, but coordinate independent tests first if it changes.
- EXEC existing private RunPhase::Live adds `observed_exit: Option<i32>`, `exit_observed_at: Option<Instant>`, `cancel_requested: bool`.
- EXEC private `poll_chunks_at(&mut self, run: RunId, now: Instant) -> Result<Vec<AgentChunk>, ExecError>`; public AgentPort::poll_chunks calls this with Instant::now. Exact deadline tests call the private seam in a child test module. No ClockPort, public test-only API or sleeps needed.
- `poll_live_if_needed(process: &mut dyn ProcessPort, run: &mut ActiveRun, now: Instant)` receives controlled time. Skeleton ignores now and still uses the old final drain, so EOF/deadline assertions fail behaviorally.
- FakeProcess skeleton fills added completion fields with Open. GREEN will make existing finish/cancel report settled streams coherently; independent scripted doubles model exit before EOF.
- HOST `cancel_run` and UI `pollRunStream` / `cmdCancelRun` signatures already exist and remain unchanged. Only their approved bodies may change after valid RED.

## Locked observable ordering for implementation after RED

1. Capture available stdout then stderr from a poll and enqueue nonempty chunks. Preserve each stream's captured ordering; no cross-stream wall-clock order guarantee.
2. Stream Error yields one Failed (`PROCESS_OUTPUT_READ_FAILED`) after captured chunks; attempt current direct-child cancel once if still running. No new tree-kill policy.
3. Observe direct-child exit with unchanged try_wait meaning. Save first observed code/time; do not reset deadline on later polls/chunks.
4. If both EOF and child exited, enqueue one Exited with code classification or approved cancellation intent. EOF completion wins at exact 2,000 ms.
5. Otherwise if first-exit elapsed >=2,000 ms, enqueue one Failed (`PROCESS_OUTPUT_INCOMPLETE`) naming open streams; retain captured data and do not emit Exited.
6. Cancel request is idempotent, marks intent after successful existing process cancel, and does not finish/emit terminal prematurely. If exit was already observed before cancel, preserve natural exit classification.
7. HOST cancel acknowledges only and must not consume a poll. Existing subsequent poll terminal performs lease reconciliation once.
8. UI empty poll continues existing cadence; cancel keeps active run/generation and says pending/draining. Only actual terminal finishes UI. A rejected cancel must leave ongoing poll intact.
