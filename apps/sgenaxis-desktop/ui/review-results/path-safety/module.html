Project Document Persistence — Path Safety

PD-RUST-PATH-SAFE-01 · READY_FOR_GREEN yellow · Independent TDD gate pending · No release or architecture approval claimed

Purpose and scope

Enforce the existing scene contract: only project-relative documents may reach the filesystem. Changes remain inside existing HOST path validation functions; public signatures, ownership, ports and transaction policy are unchanged. Domain behavior and filesystem adapter implementation are outside scope.

Architecture and responsibility

Driving adapter: UI / Tests
  → HOST scene save/load/exists and design save/load/preview (input façade)
  → normalize scene relative path → join_project_rel (validation boundary)
  → FileSystemPort (output port)
  ← FakeFileSystem / StdFileSystem (driven adapters)
System boundary: project document operations; project binding remains caller-owned.
scene_doc → uidesign_doc::join_project_rel → std::path
scene_doc + uidesign_doc → FileSystemPort ← filesystem adapters
State ownership: callers own document/project state; filesystem holds persisted data.
Mutation: only after path validation, through existing filesystem port.
Transaction: validate → mkdir → existing atomic-write port; no new transaction mechanism.

Contracts and invariants

  • Reject embedded drive prefixes, drive-relative paths, rooted/UNC paths, parent traversal and NTFS stream syntax before filesystem access.
  • Ordinary nested relative paths and legacy scene extensions remain supported.
  • Rejected scene requests preserve the existing document.
  • No new port, manager, state owner or public API. No direct UI filesystem path authority.
