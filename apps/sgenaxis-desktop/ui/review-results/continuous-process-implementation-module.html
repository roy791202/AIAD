architecture

A1 System context
Host drives EXEC through AgentPort. EXEC invokes ProcessPort; StdProcess owns native Child and pipe-reader resources. No Domain behavior change.
A2 Hexagonal view
Host / UI projection [driving adapter]
  -> AgentPort [existing input]
  -> EXEC CliAgentAdapter / ActiveRun [application; event authority]
  -> ProcessPort [existing output abstraction]
  <- StdProcess [driven OS adapter] -> native child + stdout/stderr readers
  <- FakeProcess / scripted doubles [test adapters]
Domain core: unchanged; no OS or timer dependency enters domain.
A3 Dependency view
HOST -> EXEC -> sgenaxis-ports
sgenaxis-adapters -> sgenaxis-ports
StdProcess -> std::process / std::io / std::sync
EXEC must not import StdProcess, Child, reader threads or native pipe types.
Tests compose concrete adapters; production dependency direction remains unchanged.
A4 Responsibilities
ports/process.rs
Portable output plus independent stream completion contract; try_wait retains child-exit meaning.
adapters/std_process.rs
Own Child, buffers and Open/EOF/Error reader observations; nonblocking drain.
adapters/fake.rs
Preserve coherent existing FakeProcess finish/cancel behavior under approved EOF extension.
exec/cli.rs
Own run phase, observed child exit, drain deadline, event ordering and terminal exactly-once.
A5 Input ports
AgentPort start_run / poll_chunks / cancel unchanged.
A6 Output ports
ProcessPort start / try_wait / cancel unchanged. PROPOSED ProcessOutput adds per-stream completion observations; this is a public contract change requiring approval.
A7 Driving adapters
Existing host callers and module contract tests; no new driving adapter.
A8 Driven adapters
Existing StdProcess and FakeProcess; no new production adapter.
A9 Dependency direction
Technology depends on the portable port. Application consumes the port, not the concrete process adapter.
A10 State ownership
StdProcess authoritative for native child exit and stream read status; EXEC authoritative for run state/event publication. Host/UI receives projections. No hidden global state.
A11 Mutation boundary
Reader thread mutates its own synchronized buffer/status; StdProcess observes child. Only EXEC enqueues run events and marks run finished. UI cannot set EOF/exit status.
A12 Transaction boundary
One stream drain atomically observes available bytes and completion/error under the same mutex. EOF becomes visible only after all captured bytes precede it. EXEC enqueues captured chunks before terminal and marks finished exactly once. No multi-stream wall-clock ordering guarantee.
A13 External boundary
OS direct child and inherited pipe handles. Descendants are outside kill ownership. No Agent network, API or MCP interaction.
A14 Forbidden dependencies
  • Domain -> OS/process
  • EXEC -> StdProcess or Child
  • reader -> EXEC event queue
  • UI -> mutable process state
  • blocking reader joins inside try_wait/try_read/poll_chunks
  • try_wait None after observed child exit
  • EOF inferred from one or many empty reads

locked_contracts

  • id
    INV-PROC-01
    meaning
    try_wait None means direct child not observed exited; Some(code) remains immediately observable and sticky regardless of EOF.
  • id
    INV-PROC-02
    meaning
    Empty data with Open never proves EOF. Each stream independently has Open/Eof/Error and sticky settled state.
  • id
    INV-PROC-03
    meaning
    All captured chunks precede exactly one terminal; after terminal no chunks and no repeated terminal. Cross-stream order is not guaranteed.
  • id
    INV-PROC-04
    meaning
    Success requires child code 0 and both Eof; nonzero exit also waits for both Eof. Reader failure/timeout never reports success.
  • id
    INV-PROC-05
    meaning
    Cancel is direct-child-only and idempotent; valid cancellation cannot bypass output-drain honesty.
  • id
    INV-PROC-06
    meaning
    No poll blocks waiting for reader EOF, native process exit, mutex acquisition beyond existing locking, or thread join. Existing cancel wait behavior is not relabelled nonblocking.
  • id
    INV-PROC-07
    meaning
    Deadline does not extend on new bytes; at equality complete dual EOF wins, otherwise incomplete failure. Actual wall time can exceed bound between caller polls.
  • id
    INV-PROC-08
    meaning
    A failure does not roll back delivered chunks. Errors are observable; fixtures cannot classify environment/compile errors as intended RED.

implemented_details

adapter
Each stream owns bytes + sticky completion under one mutex. EOF only on read0; Interrupted retries; other read errors retain buffered data and Error. Public try_read reports capture mutex poison as PortError, not successful empty output. Child exit meaning unchanged.
EXEC
Private controlled-Instant seam; first child exit observed once; data does not reset deadline; bothEOF wins exact deadline equality. Reader error Failed precedes success decision. Pending cancellation reaches direct child once and drains; already-observed natural exit is not reclassified. Finished runs never produce further chunks/terminal.
HOST
cancel_run acknowledges request with existing BoardView and never polls/consumes chunks; existing poll terminal reconciliation releases lease.
UI
Only pollRunStream and cmdCancelRun changed. Empty batches continue poll; pending cancel keeps run/generation and shows draining. Async ACK/error verifies run/generation to avoid reviving finished UI. Terminal board may clear activeRunId before continuation; actual terminal still finishes displayed classification.
