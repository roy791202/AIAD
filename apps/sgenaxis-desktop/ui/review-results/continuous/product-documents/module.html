executive_meaning

The product already has several formats with different validation and roundtrip behavior. Preserve these formats. First make current guarantees and gaps explicit; do not invent one universal schema or automatically migrate documents. The Rust .ess packet is a strict read-only consumer, not the frontend scene loader or a replacement serializer.

architecture_current_views

hexagonal_roles_actual
Browser UI commands [driving]
 -> JS scene/arch/design encode/decode + mutable document state [frontend application, combined in app.js]
 -> Tauri scene_save/scene_load or uidesign_* [input boundary]
 -> HOST scene_doc / uidesign_doc [application]
 -> FileSystemPort [output port]
 <- filesystem adapter [driven infrastructure]
Separate .ess packet CLI -> HOST module_packet -> SPEC pure projection + EssDecoderPort <- ProductEssDecoder XML adapter.
This describes current responsibilities; frontend codec/state/UI concerns are not physically separated into hexagonal modules.
dependency_map_actual
app.js -> Tauri IPC names -> HOST functions -> FileSystemPort
uidesign_doc -> typed serde JSON DTOs
scene_doc -> opaque UTF-8 text persistence (no product XML validation)
module_packet -> SPEC SourceElement projection + FileSystemPort + EssDecoderPort
ProductEssDecoder -> XML library; SPEC does not depend on XML SDK.
No dependency from Domain to DOM or filesystem is proposed.
ownership
Frontend archDoc/designDoc/board projection state lives in app.js. HOST saves supplied scene text without parsing. Dedicated design save/load uses typed Rust DTOs. Packet has derived source-hashed projection only; it cannot own or mutate the source.
mutation
Frontend apply functions mutate local documents and UI; scene_save writes a project-scoped text file through write_atomic. Packet performs no writes. Raw design hints/flags are not acceptance authority.
transactions
Integrated .ess parser builds scene object before apply. Rendering/apply failures after mutation have no explicit rollback. Split load applies work then arch then design, so late parse failure can leave earlier state changed. Split save performs three separate atomic file calls; there is no declared three-file atomic commit. No new transaction semantics are approved here.
boundaries
Document formats are external contracts. No automatic format unification, migration service, new parser, repository, port or manager is justified by this audit.

identity_and_reference_current

  • Architecture node.id, edge.id, port ids and Layer.modules[{slotId,moduleId,memberIds}] are distinct source concepts; moduleId is semantic identity, slotId is UI placement identity. They must not be assumed interchangeable.
  • Frontend arch decode defaults missing moduleId to slotId, fills absent ports and legacy members; ensureArchDocUuids uses a shared used-ID set across nodes/slots/modules/edges/events and replaces missing/duplicate IDs. The helper does not itself remap all references. This is compatibility normalization, not strict validation or proof of valid graph identity.
  • Frontend syncArchAssignmentsFromModules assigns moduleRef/layerRef from membership. The strict packet instead validates module/slot uniqueness separately, member existence and matching moduleRef/layerRef plus edge-node/direction-specific port references; it does not repair IDs.
  • Dedicated DesignDoc.validate checks format/version/product_pass only. Duplicate design node IDs, missing parents, selection references or parent cycles are not validated there.
  • UI architecture uiDefinitionRef is a document reference/hint; it does not prove a subset of design node ownership. Existing readonly packets emit UI_SCOPE_UNRESOLVED and UI_DOCUMENT_UNRESOLVED, remain NOT_READY and do not open external design files.

unknown_fields_and_roundtrip

  • path
    .ess work/task
    current
    Unknown task object fields are encoded in <extra encoding=json> CDATA and merged back. Bad extra JSON is silently ignored. Unknown board/root/meta fields do not have general preservation logic.
    risk
    Not an arbitrary XML-preserving serializer; extra merge can overwrite known task keys.
  • path
    .esml architecture
    current
    Writer and parser enumerate known attributes/children. specProps string values and known payload JSON are supported; arbitrary unknown XML elements/attributes are not retained in a general extension store.
    risk
    Unknown content and unsupported node kinds can disappear during decode/re-save. Missing/duplicate identity may be regenerated.
  • path
    .ess design
    current
    Known node fields/hints and props only. Scalar props serialized as attributes; decoder converts true/false to bool and decimal-looking strings to Number. null props are omitted. Object/array props use JSON CDATA; invalid JSON is ignored.
    risk
    String '001'/'true', null and arbitrary node/meta fields cannot be promised type-preserving roundtrip. Non-UI node types filtered; empty designs may become blank Form.
  • path
    .esui JSON
    current
    JSON deep-copy writer generally retains existing object fields; apply filters node types and stamps UI fields. It rewrites format/product_pass/meta.updatedAt/encoding.
    risk
    Unknown UI node types removed; exact bytes/timestamps not stable; scope/UI stamps are added.
  • path
    .sgendesign Rust JSON
    current
    Typed serde DTOs without flattened extension storage or deny_unknown_fields ignore unrecognized top-level/Meta/Node keys; arbitrary props JSON preserved. Frontend design fields meta.gridSize/formSize, node.scope/uiExclusive are not declared Rust fields.
    risk
    Those fields can be lost across dedicated IPC DTO roundtrip. This is distinct from merely saving scene text.
  • path
    CDATA text
    current
    boardTaskToXml extra and designNodeToXml object props concatenate JSON directly inside CDATA.
    risk
    A JSON string containing literal ]]> can terminate CDATA and produce malformed XML. Static candidate; no behavior reproduction executed in this task.
  • path
    packet projection
    current
    SourceElement retains arbitrary attrs/text/ordered children within selected module facts and source selectors; exact source bytes bound by SHA256. Unrelated bodies intentionally excluded.
    risk
    Packet is a bounded read-only subset, not a lossless load/save migration document or approval source.
